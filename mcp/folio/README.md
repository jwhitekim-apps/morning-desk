# my-task / folio MCP 서버

[`my-task`](../../README.md)의 **논문 목록 읽는 부분**입니다. 폴리오(Zotero 논문 뷰어 웹앱)가 Supabase의 `folio_papers` 테이블에 동기화해 둔 논문 목록을 **읽기 전용**으로 조회하는 MCP(Model Context Protocol) 서버입니다. 폴리오의 코드와 DB 스키마는 건드리지 않습니다. 코드는 직접 작성했고 외부 코드를 가져오지 않았으며, 의존성은 MCP SDK와 zod뿐입니다(Supabase 클라이언트 라이브러리 없이 표준 `fetch`로 PostgREST를 부릅니다).

## 하는 일

| 도구 | 종류 | 설명 |
|---|---|---|
| `list_recent_papers` | 읽기 | 논문 목록을 **동기화 시각 최신순**으로. `since`(날짜 `YYYY-MM-DD`는 한국 시간 자정, 또는 ISO 8601 일시)와 `maxResults`(기본 200, 최대 500). 더 있으면 `truncated: true`. 제목이 비어 있으면 "(제목 없음)" |
| `search_papers` | 읽기 | 제목에 검색어가 든 논문(대소문자 무시, 최신순). 검색어는 **글자 그대로** 찾습니다(`% * , ) ( _ \ [` 등 특수문자 포함) |

**일부러 없는 것**: 쓰기 도구 전부, 새 논문 판단, 의미(임베딩) 검색. 요청은 오직 한 곳의 `GET`뿐이고, 코드에 다른 요청 방식이 없습니다(`test/registry.test.ts`가 도구 목록과 요청 방식을 고정합니다).

## 동기화 시각의 한계 (중요)

응답의 `syncedAt`은 **Zotero에서 마지막으로 동기화된 시각**입니다. 논문을 **처음 저장한 시각이 아니며**, 정보를 다시 가져올 때마다 바뀝니다. 그래서 이 값만으로는 "새 논문"이라고 판단할 수 없습니다. 도구 설명과 모든 응답의 `note`에 이 사실을 적어 두었습니다. 새 논문 판단이 필요하면 호출하는 쪽(`assistant-app`)이 "처음 본 시점"을 따로 기록해야 합니다. 정석은 폴리오 테이블에 `created_at`을 추가하는 것인데, 폴리오 프로젝트의 변경이라 여기서는 하지 않았습니다.

날짜·시각은 모두 한국 시간(`+09:00`)으로 나옵니다.

## 키 방침

| 단계 | 키 | 상태 |
|---|---|---|
| 개발·시험 (지금) | 기존 **서비스 키**(관리자 권한) | 허용. 로그와 응답에 나타나지 않음 |
| **운영 전** | 읽기 전용으로 제한된 키 (읽기 전용 **뷰**와 그 뷰만 읽는 키, 또는 읽기 전용 역할 + 행 수준 보안) | **교체해야 함** |

서비스 키는 관리자 권한이라 서버가 뚫리면 폴리오 데이터 전체에 닿습니다. 그래서 홈 서버에서 매일 자동 실행을 시작하기 전에 제한된 키로 바꿉니다. 서버는 키 종류와 무관하게 동작합니다(`FOLIO_TABLE`로 뷰 이름을 지정하면 됩니다). 폴리오가 쓰는 Supabase 프로젝트의 설정(뷰, 역할, 정책)은 자동으로 바꾸지 않고 사용자가 확인한 뒤에만 합니다. 결정 기록은 `openspec/changes/**/folio-mcp/design.md`에 있습니다.

## 설정과 실행

Node 20 이상. 이 폴더(`mcp/folio/`) 안에서 합니다.

```bash
npm ci --ignore-scripts   # 잠금 파일 그대로 설치, 의존 패키지의 설치 스크립트는 실행하지 않음
npm run build
npm test
```

환경 변수(서버를 띄우는 쪽에서 지정):

| 이름 | 설명 |
|---|---|
| `FOLIO_SUPABASE_URL` | Supabase 프로젝트 주소(`https://...supabase.co`). 키가 전송되므로 https만 허용(localhost 제외) |
| `FOLIO_SUPABASE_KEY` | 접속 키(위 키 방침 참고) |
| `FOLIO_TABLE` | 테이블 또는 뷰 이름(기본 `folio_papers`) |

에이전트에 연결:

```json
{ "mcpServers": { "folio": { "command": "node", "args": ["/절대/경로/my-task/mcp/folio/dist/index.js", "serve"], "env": { "FOLIO_SUPABASE_URL": "...", "FOLIO_SUPABASE_KEY": "..." } } } }
```

## 오류

원인별로 구분된 코드로 알립니다: `config_error`(설정 누락·잘못된 주소), `auth_failed`(키가 틀림·읽기 권한 없음), `table_not_found`(테이블/뷰가 없음), `validation_error`, `rate_limited`(기다릴 시간 포함), `unavailable`(서버 일시 장애, 읽기라서 짧게 재시도 후), `upstream_error`(응답 구조가 바뀜: 행에 `item_key`나 `synced_at`이 없을 때 조용히 넘기지 않고 오류로 알림).

## 개인정보

- 키는 도구 응답과 로그에 나타나지 않습니다. 로그는 허용한 필드(건수, 소요 시간, 오류 분류)만 남기는 방식이라 논문 제목도 기록되지 않습니다(`test/privacy.test.ts`).
- 오류 응답은 데이터베이스가 보낸 설명문을 쓰지 않고 고정 문구와 분류 코드를 씁니다.
