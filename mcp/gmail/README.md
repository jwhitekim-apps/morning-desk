# my-task / gmail MCP 서버

[`my-task`](../../README.md)의 **메일 연결 부분**입니다. Gmail을 **읽기 전용**으로 검색하고 본문을 읽는 MCP(Model Context Protocol) 서버입니다. 메일이 중요한지, 마감이 언제인지 판단하는 일은 에이전트의 몫이고, 이 서버는 안전하게 읽어서 돌려주기만 합니다.

## 출처

이 서버의 코드는 **직접 작성했고, 외부 코드를 가져오지 않았습니다.** 작성 전에 기존 Gmail MCP 서버를 조사했고(근거는 `openspec/changes/archive/` 또는 `openspec/changes/gmail-mcp/design.md`의 "조사 결과"), 읽기 전용 서버 [`@jdickey1/mcp-gmail`](https://github.com/jdickey1/claude-skills/tree/main/mcp-servers/gmail)(MIT)의 구조를 참고했습니다(검색 때 필요한 필드만 요청하기, 미리보기의 HTML 엔티티 해제, 메일 부분을 재귀로 훑기). 코드는 복사하지 않았습니다.

## 하는 일

| 도구 | 종류 | 설명 |
|---|---|---|
| `auth_status` | 인증 | 로그인되어 있는지 확인. 토큰 값은 돌려주지 않음 |
| `search_emails` | 읽기 | Gmail 검색식 + 기간(일) + 최대 개수(기본 20, 최대 100)로 검색, 최신순. 각 메일에 `threadSubject`(같은 스레드에서 가장 먼저 받은 메일의 제목)가 붙음. 더 있으면 `truncated: true` |
| `read_email` | 읽기 | 메일 번호로 본문을 텍스트로 읽음. 일반 텍스트 우선, 없으면 HTML에서 태그 제거. 6000자 상한, 잘리면 `truncated`와 `originalLength` |

**일부러 없는 것**: 메일 보내기, 삭제, 휴지통, 보관, 라벨 변경, 읽음 표시, 첨부파일, 스레드 전체 읽기. 요청하는 권한도 `gmail.readonly` 하나뿐이라서, 같은 토큰으로는 구글이 발송·삭제를 거부합니다. 도구가 코드에 존재하지 않으면 모델이 실수로도 부를 수 없다는 원칙입니다(`test/registry.test.ts`가 도구 목록과 요청 권한, 요청 방식을 고정합니다).

응답에는 `notice`가 붙습니다: 메일 내용은 외부에서 온 데이터이며 지시가 아니라는 표시입니다. 프롬프트 주입을 막는 본체는 에이전트 쪽(소스 내용을 데이터로만 다루고 쓰기를 제한)에 있고, 이것은 마지막 안전망입니다.

날짜는 모두 한국 시간(`+09:00`)으로 나옵니다.

## 준비와 로그인

Node 20 이상. 이 폴더(`mcp/gmail/`) 안에서 합니다.

```bash
npm ci --ignore-scripts   # 잠금 파일 그대로 설치, 의존 패키지의 설치 스크립트는 실행하지 않음
npm run build
npm test
```

**1) OAuth 클라이언트 준비** — [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 고르고 다음을 합니다.

1. "API 및 서비스 → 라이브러리"에서 **Gmail API**를 사용 설정합니다.
2. "OAuth 동의 화면"을 설정하고(외부), 범위에 `gmail.readonly`를 추가합니다.
3. "사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID"에서 유형을 **데스크톱 앱**으로 만들고 JSON을 내려받습니다.
4. 내려받은 JSON의 `client_id`와 `client_secret`을 루트 `.env.local`의 `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`에 넣습니다(내려받은 파일은 지웁니다).

**2) 로그인** (한 번)

```bash
node dist/index.js login
```

브라우저가 열리면 읽기 전용 접근을 승인합니다. 리프레시 토큰은 루트 `.env.local`(권한 600)의 `GMAIL_REFRESH_TOKEN` 줄에 저장되고, 액세스 토큰은 실행 중 메모리에만 둡니다. 저장 위치는 `MY_TASK_ENV_FILE`(비서가 넘김), 없으면 저장소 루트의 `.env.local`입니다. 파일 끝의 `# --- 토큰 (자동 갱신, 직접 고치지 마세요)` 구역은 서버가 고쳐 쓰므로 손으로 고치지 않습니다. 예전처럼 홈 폴더에 토큰 파일이 남아 있으면 `agent`에서 `node dist/index.js migrate-tokens`(먼저 `--dry-run`)로 옮깁니다. 로그인은 서버가 도는 컴퓨터에서 브라우저로 해야 합니다(로컬 주소로 되돌아오는 방식). 로그아웃(`node dist/index.js logout`)은 그 줄을 지웁니다.

## 동의 화면 "테스트" 상태와 7일 만료

OAuth 동의 화면이 **"테스트"** 상태이면 구글이 **갱신 토큰을 7일 뒤 만료**시킵니다. 만료되면 도구가 `auth_expired`와 함께 "다시 로그인하라"는 안내를 돌려줍니다. 대응은 둘 중 하나입니다.

- **"프로덕션으로 게시"** (권장): 동의 화면을 게시 상태로 바꾸면 만료되지 않습니다. 개인용(사용자 100명 미만)이면 심사 없이 쓸 수 있는 것으로 알고 있으며(구글 정책이라 바뀔 수 있으니 콘솔의 안내를 확인하세요), 로그인 때 "확인되지 않은 앱" 경고가 뜨는데 본인 앱이므로 "고급 → 이동"으로 진행하면 됩니다.
- 테스트 상태를 유지하고 7일마다 `login`을 다시 합니다.

## 에이전트에 연결

MCP 설정에 표준입출력 서버로 등록합니다.

```json
{ "mcpServers": { "gmail": { "command": "node", "args": ["/절대/경로/my-task/mcp/gmail/dist/index.js", "serve"] } } }
```

## 개인정보

- 토큰과 OAuth 클라이언트 비밀값은 도구 응답과 로그에 나타나지 않습니다.
- 로그는 허용한 필드(건수, 소요 시간, 오류 분류 같은 숫자·짧은 값)만 남기는 방식이라 메일 제목·본문·보낸 사람이 기록되지 않습니다(`test/privacy.test.ts`).
- 오류 응답은 구글이 보낸 설명문을 그대로 쓰지 않고 고정 문구와 분류 코드를 씁니다(설명문에 메일 내용이 섞일 수 있기 때문).
- 메일 본문은 `read_email`의 응답으로만 나갑니다. 어디로 흘러가는지는 에이전트(`assistant-app`)의 책임이며, 로컬 LLM으로만 보내는 것이 전제입니다.
