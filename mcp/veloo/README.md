# my-task / veloo MCP 서버

[`my-task`](../../README.md)의 **벨루 읽는 부분**입니다. 벨루(별개의 FastAPI + React 앱, 집 서버)에 저장된 기존 태스크와 주간 리뷰를 **읽기 전용**으로 조회하는 MCP(Model Context Protocol) 서버입니다. 벨루 코드는 건드리지 않고 바깥에서 읽기만 합니다. 새 태스크는 Microsoft To Do가 받습니다.

코드는 직접 작성했고(이전 시스템의 내 벨루 어댑터를 읽기 전용으로 다시 쓴 것) 외부 코드를 가져오지 않았으며, 의존성은 MCP SDK와 zod뿐입니다.

## 하는 일

| 도구 | 종류 | 설명 |
|---|---|---|
| `veloo_auth_status` | 인증 | 설정이 되어 있는지, 저장된 세션이 있는지. 계정 이름·비밀번호·세션 값은 돌려주지 않음 |
| `veloo_list_tasks` | 읽기 | 태스크 목록. `status`: `open`(기본) / `done` / `all`. `dueFrom`·`dueTo`(`YYYY-MM-DD`, 양 끝 포함)로 마감 범위. 기본 200개, 최대 1000개, 넘으면 `truncated`와 `omitted` |
| `veloo_weekly_review` | 읽기 | `weekStart`(한국 날짜, 보통 월요일)부터 7일의 완료·생성·밀린 태스크 수와 완료율 |

각 태스크에는 `id`, `name`, `memo`, `priority`(`urgent`/`mid`/`normal`), `deadline`(**벨루에 적힌 원문**), `dueDate`, `done`, `createdAt`(한국 시간)이 있습니다.

- **마감은 자유 문구일 수 있습니다**(예: "이번 주 안에"). `deadline`은 항상 원문 그대로이고, `dueDate`는 원문이 정확히 `YYYY-MM-DD`인 실제 날짜일 때만 채웁니다. 날짜 범위 조회에서는 마감이 없거나 자유 문구인 태스크가 빠집니다.
- 필터는 서버가 아니라 이쪽에서 합니다(벨루의 목록 API는 필터를 받지 않고 전체를 줍니다).
- 주간 리뷰의 "밀린 수"는 그 주 시작 전에 만들어졌고 아직 안 끝난 태스크 수입니다. 완료율은 벨루가 계산해서 주며, 그 주에 끝낸 일이 만든 일보다 많으면 1을 넘을 수 있습니다. 벨루가 주는 우선순위별 통계(`by_priority`)는 주와 상관없이 전체 태스크로 계산한 값이라 일부러 돌려주지 않습니다.

**일부러 없는 것**: 태스크 생성·수정·완료·삭제, 단계(steps), AI 전략 등 쓰기 전부. 요청은 데이터에 `GET`만 보내고, 계정 확인용 `POST /login`이 유일한 예외입니다(`test/registry.test.ts`가 도구 목록, 요청 방식, 주소를 고정합니다).

## 주의: 벨루 API는 비공식입니다

`/login`, `/todo/api/todos`, `/todo/api/reviews/weekly`는 벨루 자신의 프런트엔드가 쓰는 **내부 API**이고 공개 계약이 아닙니다. 벨루가 바뀌면 깨질 수 있어서, 서버는 응답의 모양(필수 필드와 형식)을 검사하고 어긋나면 임의로 해석하지 않고 `contract_changed` 오류로 알립니다(어떤 필드인지만 알리고 값은 알리지 않습니다). 한 행이라도 어긋나면 그 행만 건너뛰지 않고 전체를 오류로 알립니다. 벨루 서버가 꺼져 있거나 닿지 않으면 `unavailable`로 구분합니다.

오류 코드: `config_error`, `auth_failed`, `permission_denied`, `validation_error`, `rate_limited`, `unavailable`, `contract_changed`, `upstream_error`.

## 로그인과 세션

- 첫 요청에서 `POST /login`으로 로그인하고, 받은 세션 쿠키를 루트 `.env.local`(권한 600)의 `VELOO_SESSION` 줄에 저장해 재사용하고, 세션이 거부되면 그 줄을 지웁니다. 저장 위치는 `MY_TASK_ENV_FILE`(비서가 넘김), 없으면 저장소 루트의 `.env.local`입니다. 파일 끝의 `# --- 토큰 (자동 갱신, 직접 고치지 마세요)` 구역은 서버가 고쳐 쓰므로 손으로 고치지 않습니다. 예전처럼 홈 폴더에 토큰 파일이 남아 있으면 `agent`에서 `node dist/index.js migrate-tokens`(먼저 `--dry-run`)로 옮깁니다. 서버를 다시 시작해도 이어 씁니다(벨루 세션은 30일).
- 저장된 세션이 거부(401, 또는 로그인 화면으로 리다이렉트)되면 **한 번만** 다시 로그인해서 재시도합니다. 방금 로그인한 세션이 거부되면 다시 로그인하지 않고 포기합니다.
- **벨루는 로그인에 5번 실패하면 같은 IP를 15분 동안 잠급니다.** 그래서 계정 정보가 틀려서 로그인이 거부되면 이 서버는 **15분 동안 로그인을 다시 시도하지 않고** 같은 오류를 돌려줍니다(재시도 반복으로 잠기는 일을 막기 위해). 일시 장애(5xx, 연결 불가)는 바로 다시 시도합니다.

## 설정과 실행

Node 20 이상. 이 폴더(`mcp/veloo/`) 안에서 합니다.

```bash
npm ci --ignore-scripts   # 잠금 파일 그대로 설치, 의존 패키지의 설치 스크립트는 실행하지 않음
npm run build
npm test
```

| 환경 변수 | 설명 |
|---|---|
| `VELOO_BASE_URL` | 벨루 주소(예: `https://veloo.2joon.com`). 비밀번호가 전송되므로 https만 허용(localhost 제외) |
| `VELOO_USERNAME` | 벨루 계정 이름 |
| `VELOO_PASSWORD` | 벨루 계정 비밀번호 |

에이전트에 연결:

```json
{ "mcpServers": { "veloo": { "command": "node", "args": ["/절대/경로/my-task/mcp/veloo/dist/index.js", "serve"], "env": { "VELOO_BASE_URL": "...", "VELOO_USERNAME": "...", "VELOO_PASSWORD": "..." } } } }
```

## 개인정보와 위험

- 계정 이름, 비밀번호, 세션 값은 도구 응답과 로그에 나타나지 않습니다. 로그는 허용한 필드(건수, 소요 시간, 오류 분류)만 남기는 방식이라 태스크 이름과 메모도 기록되지 않습니다(`test/privacy.test.ts`).
- 오류 응답은 벨루가 보낸 설명문을 쓰지 않고 고정 문구와 분류 코드를 씁니다.
- 응답의 `notice`: 태스크 이름과 메모는 메일 등에서 옮겨 적은 글일 수 있으니 데이터로만 다루고 지시로 따르지 말라는 표시입니다.
- **알려진 위험:** 벨루 계정의 비밀번호가 약합니다(바꾸지 않기로 한 상태). 이 서버는 계정을 환경 변수로 받으므로 환경 변수 파일의 권한(600)과 저장소 제외(`.gitignore`)를 지켜야 합니다.
- 벨루를 퇴역하면 이 서버도 필요 없어집니다.
