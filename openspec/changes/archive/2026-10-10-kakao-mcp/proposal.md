# Proposal

## Why

비서의 브리핑은 카카오톡 "나에게 보내기"로 나간다. 카카오는 대화를 읽는 API를 주지 않아서 **읽기는 불가능하고 보내기만 가능**하다. 이전 시스템에서 토큰 갱신과 전송은 실제로 동작했다(200자 말풍선, 갱신 시 새 리프레시 토큰 저장). 이 전송 능력을 에이전트가 쓰는 **MCP 도구**로 분리하되, 받는 사람은 나 자신으로 고정해서 모델이 실수로도 다른 사람에게 보낼 수 없게 한다.

## What Changes

- `mcp/kakao/`에 **카카오톡 나에게 보내기 전용 MCP 서버**를 만든다: 메시지 하나 보내기, 여러 통(최대 3) 순서대로 보내기, 보내지 않고 내용만 확인하는 드라이런.
- 받는 사람 매개변수는 두지 않는다(나에게만). 친구에게 보내기 도구는 만들지 않는다.
- 토큰 갱신을 처리하고, 갱신으로 새 리프레시 토큰이 오면 로컬 파일(권한 600)에 저장해서 다음 실행에서 이어 쓴다.
- 글자 수 한도(200자)를 넘으면 자르지 않고 **오류로 알린다**. 나누고 서식을 입히는 일은 비서 앱이 한다.
- **범위 밖**: 카카오톡 읽기(불가능), 친구에게 보내기, 알림이 울리지 않는 문제의 해결(카카오 나와의 채팅 메모는 푸시가 오지 않을 수 있다는 알려진 한계), 브리핑 구성.

## Capabilities

### New Capabilities
- `kakao-send-tools`: 에이전트가 카카오톡 나에게 보내기로 텍스트를 보내는 MCP 도구 계약.

## Impact

- 새 코드: `mcp/kakao/`.
- 외부 시스템: 카카오 API(`kauth.kakao.com/oauth/token`, `kapi.kakao.com/v2/api/talk/memo/default/send`). 카카오 개발자 앱의 REST API 키와 클라이언트 시크릿, 리프레시 토큰(약 60일 수명)이 필요하다. 이전에 발급한 값을 다시 쓸 수 있는지 확인한다.
- 알려진 한계: 보낸 메시지는 도착하지만 폰 알림이 울리지 않는다는 것이 실제로 확인되었다. 이 서버는 전송만 책임지고 알림 문제는 별도 변경이다.
- 개인정보: 메시지 본문은 로그에 남기지 않고 길이만 기록한다.
