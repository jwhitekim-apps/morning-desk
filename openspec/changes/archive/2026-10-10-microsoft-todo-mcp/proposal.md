# Proposal

## Why

앞으로의 개인 비서는 태스크 앱(Microsoft To Do)을 사람의 유일한 입력 창구로 두고, 로컬 LLM 에이전트가 MCP 도구로 그 태스크를 읽고 새 태스크를 추가합니다. 오픈소스 `fabienbutz/microsoft-todo-mcp`를 필요한 부분만 골라 `mcp/microsoft-todo/`에 가져왔고(타입 검사, 린트, 테스트 27개, 빌드 통과), 위험한 도구(수정, 완료, 삭제, 목록 관리, 체크리스트)는 코드에서 뺐습니다.

그런데 두 가지가 남아 있습니다.
- 가져온 서버가 **어떤 계약을 지키는지 문서가 없습니다.** 도구 표면을 허용 목록으로 고정하는 테스트는 있지만, 에이전트가 의존할 동작(권한 범위, 토큰 보관, 중복 방지)이 스펙으로 확정되어 있지 않습니다.
- 아침 브리핑에 필요한 질의가 지금 도구로는 불편합니다. 오늘, 임박, 밀린 일을 알려면 목록마다 태스크를 따로 불러서 모아야 하고, 마감 시각의 시간대(한국 표준시) 처리가 검증되지 않았습니다.

또한 실제 Microsoft 계정으로 로그인해서 읽고 써 본 적이 아직 없습니다.

## What Changes

- Microsoft To Do MCP 서버의 **계약을 스펙으로 확정**합니다: 인증과 토큰 보관, 권한 범위, 도구 표면 고정, 중복 없는 태스크 추가.
- **마감 범위 조회 도구**를 추가합니다. 모든 목록에 걸쳐 미완료 태스크를 기간으로 한 번에 가져옵니다(밀린 일 포함 선택).
- **시간대 처리**를 한국 표준시 기준으로 확정하고 검증합니다.
- 기본 클라이언트로 **실제 로그인 검증**을 합니다: 읽기 전용으로 먼저, 이어서 시험 태스크 1건 추가.
- **범위 밖**: 태스크 수정, 완료, 삭제, 목록 관리, 체크리스트(에이전트에게 주지 않기로 한 도구), 반복 일정, 변경분 조회(delta), 에이전트와 다른 데이터 소스(Gmail, GitHub, 폴리오), 브리핑 전송, 본인 Azure 앱 등록으로의 전환.

## Capabilities

### New Capabilities
- `microsoft-todo-tools`: 에이전트가 Microsoft To Do의 태스크를 읽고 새 태스크를 추가하는 MCP 도구 계약(인증, 권한 범위, 도구 표면, 조회, 추가).

## Impact

- 코드: `mcp/microsoft-todo/src/` 아래에 조회 도구와 시간 변환이 추가됩니다(`todo/tasks.ts` 또는 새 파일, `tools/task-tools.ts`, `tools/registry.ts`). 테스트는 `mcp/microsoft-todo/test/`.
- 허용 도구 목록 테스트(`test/registry.test.ts`)가 새 도구 이름을 반영해야 합니다. 허용 목록에 의도적으로 한 줄을 추가하는 변경입니다.
- 외부 시스템: Microsoft Graph(`Tasks.Read`, `Tasks.ReadWrite`). 로그인 토큰은 `~/.config/microsoft-todo-mcp/token-cache.json`(파일 권한 600).
- 보안: 기본 클라이언트가 Microsoft의 Graph 명령줄 도구용 공개 클라이언트라서 동의 화면에 그 이름이 나타납니다. 본인 앱 등록으로 바꾸는 것은 다음 변경으로 미룹니다.
- 알려진 경고: `npm audit`이 의존성 취약점 10개(심각 1, 높음 4)를 보고합니다. 로컬 표준입출력 서버라서 노출은 작다고 보지만 갱신 가능 여부 확인이 필요하고, 이 변경에서는 조사만 합니다.
