# Proposal

## Why

연구와 개발 일정의 일부는 GitHub에 있다: 내게 온 리뷰 요청, 내게 배정된 이슈와 PR, 마일스톤의 마감일, 읽지 않은 알림. 에이전트가 이것을 읽을 수 있으면 메일 밖의 일정도 감지할 수 있다. 코드를 읽거나 쓰는 능력은 필요 없고, **내게 해당하는 일의 목록**만 필요하다.

## What Changes

- 먼저 **기존 GitHub MCP 서버를 조사**한다(공식 서버의 읽기 전용 설정이 충분한지, `gh` CLI를 감싼 얇은 서버가 더 나은지). 조사 결과에 따라 설정만으로 끝날 수도 있고, 직접 작성할 수도 있다.
- 필요한 도구는 읽기 전용이다: 내게 온 리뷰 요청, 내게 배정된 이슈와 PR(마일스톤 마감일 포함), 읽지 않은 알림, 선택한 저장소의 최근 활동.
- 인증은 읽기 전용 권한의 토큰(`gh auth`가 이미 있으면 그것, 아니면 읽기 전용 fine-grained 토큰)을 쓴다.
- 도구 표면은 허용 목록 테스트로 고정한다. 코멘트, 이슈·PR 생성, 머지, 푸시 같은 쓰기 도구는 노출하지 않는다.
- **범위 밖**: 모든 쓰기, 코드 내용 읽기, GitHub Actions 관리, 에이전트가 하는 판단.

## Capabilities

### New Capabilities
- `github-tools`: 에이전트가 내게 해당하는 GitHub 일(리뷰 요청, 배정, 마일스톤, 알림)을 읽기 전용으로 조회하는 MCP 도구 계약.

## Impact

- 새 코드 또는 설정: `mcp/github/` (조사 결과에 따라 코드가 거의 없을 수 있다).
- 외부 시스템: GitHub API. 현재 이 컴퓨터에는 `gh`가 `jwhitekim` 계정으로 로그인되어 있다.
- 위험: 공식 서버를 쓰면 쓰기 도구가 기본으로 포함될 수 있어서, 읽기 전용 설정이 실제로 쓰기 도구를 숨기는지 반드시 검증해야 한다. 비공개 저장소의 제목과 본문이 에이전트(로컬 LLM)에 들어갈 수 있다.
