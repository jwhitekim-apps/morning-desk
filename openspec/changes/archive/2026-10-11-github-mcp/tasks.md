# Tasks

## 1. 조사와 결정

- [x] 1.1 공식 GitHub MCP 서버의 읽기 전용 구성을 실제로 시험한다: 도구 목록을 열어 쓰기 도구가 하나도 노출되지 않는지, 필요한 조회(리뷰 요청, 배정, 마일스톤 마감, 알림)가 있는지 확인한다. 검증: 읽기 전용 설정에서 노출된 도구 목록과 판정이 `design.md`에 기록되어 있다
- [x] 1.2 1.1의 결과로 채택(설정만 사용), 직접 작성 중 하나를 정한다. 코드를 가져온다면 출처 표시를 지킨다. 검증: 결정과 근거가 문서에 있다
- [x] 1.3 읽기 전용 fine-grained 토큰을 만들고 필요한 저장소에만 권한을 준다(GitHub 설정에서 사용자가 직접). 검증: 이 토큰으로 쓰기 요청을 시도하면 권한 오류가 난다

## 2. 구현 (직접 작성으로 정해진 경우, 아니면 설정과 테스트)

- [x] 2.1 `mcp/github/`에 서버 골격(설정, 오류 분류, 로거, 도구 등록)을 만든다. 검증: 빈 도구 목록으로 서버가 시작되고 타입 검사, 린트, 테스트, 빌드가 통과한다
- [x] 2.2 리뷰 요청 도구를 만든다. 검증: 모의 테스트에서 저장소, 번호, 제목, 주소, 갱신 시각, 요청한 사람이 나오고 요청이 없으면 빈 목록이다
- [x] 2.3 배정된 이슈와 PR 도구를 만든다(마일스톤 마감 포함, 없으면 마감 없음 표시). 검증: 마일스톤이 있는 항목과 없는 항목이 각각 기대대로 나온다
- [x] 2.4 알림 도구를 만든다(읽음 표시를 바꾸지 않음). 검증: 두 번 연달아 조회해도 같은 목록이 나온다
- [x] 2.5 개수 상한과 잘림 표시, 오류 구분(인증, 권한, 요청 한도)을 넣는다. 검증: 상한을 넘는 결과에 잘림 표시가 있고, 요청 한도 초과에 다시 시도할 시각이 있다
