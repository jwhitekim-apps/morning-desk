# Proposal

## Why

입력 창구를 Microsoft To Do로 옮겨도 벨루에는 기존 태스크와 주간 리뷰가 남아 있다. 에이전트가 그것을 참고하고(예: 지난주 통계), 필요한 태스크를 To Do로 옮길 수 있게 하려면 벨루의 데이터를 읽는 길이 필요하다. 이전 시스템에서 벨루 로그인(쿠키 세션)과 목록·주간 리뷰 조회는 실제로 동작했다. 벨루는 별개의 프로젝트이므로 **코드를 고치지 않고** 바깥에서 읽기만 한다.

## What Changes

- `mcp/veloo/`에 **벨루 읽기 전용 MCP 서버**를 만든다: 태스크 목록 조회(완료 여부, 마감 범위 필터), 주간 리뷰 조회.
- 벨루 로그인 세션을 재사용하고, 세션이 만료되면 한 번만 다시 로그인한다.
- 도구 표면은 읽기로 고정하고 허용 목록 테스트가 지킨다. 태스크 생성, 수정, 삭제 도구는 만들지 않는다(새 태스크는 To Do에 쓴다).
- 이전 시스템의 벨루 어댑터를 바탕으로 하되 MCP 도구 계약에 맞게 다시 쓴다(내가 쓴 코드라 출처 문제는 없다).
- **범위 밖**: 벨루 쓰기, 벨루 코드 수정, 기존 태스크를 To Do로 옮기는 자동 이관(에이전트가 읽고 To Do 도구로 쓰는 것으로 가능하며 필요하면 별도 변경), 벨루의 다른 기능(번역기, 논문 분석기).

## Capabilities

### New Capabilities
- `veloo-tools`: 에이전트가 벨루의 태스크와 주간 리뷰를 읽기 전용으로 조회하는 MCP 도구 계약.

## Impact

- 새 코드: `mcp/veloo/`.
- 외부 시스템: 벨루 서버(`veloo.2joon.com`)의 비공식 내부 API(`/login`, `/todo/api/todos`, `/todo/api/reviews/weekly`). 벨루가 바뀌면 깨질 수 있어서 응답 모양을 검사하는 계약 테스트가 필요하다.
- 비밀: 벨루 계정 이름과 비밀번호(환경 변수). 전용 계정을 권장하지만 지금 쓰는 계정을 유지하기로 한 상태이고, 비밀번호가 약하다는 점은 알려진 위험이다.
- 벨루를 앞으로도 쓸지는 정해지지 않았다. 이 서버는 벨루가 계속 남든 퇴역하든 읽기 용도로만 필요하다.
