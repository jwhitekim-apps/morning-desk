# Proposal

## Why

이 프로젝트의 목적은 사람이 직접 입력하는 곳을 **태스크 앱 하나**(Microsoft To Do)로 줄이고, 나머지(메일, GitHub, 폴리오)는 비서가 알아서 읽어서 일정과 할 일을 찾아 브리핑하는 것이다. 이전 시스템(`veloo-secretary`, Vercel + Gemini)은 규칙과 모델 호출이 이어진 파이프라인이라 매일 같은 틀의 목록만 나왔고, 모든 결과를 사람이 검증해야 했으며, 알림이 울리지 않고, 대답할 방법이 없었다. 이번에는 **로컬 LLM이 MCP 도구들을 쥐고** 하루 한 번 소스를 훑어 브리핑하는 에이전트를 새로 만든다. 읽기는 자유롭게, 쓰기는 "태스크 추가" 하나만 허용하는 위임 구조를 유지한다.

## What Changes

- `agent/`에 **비서 앱(에이전트)** 을 만든다. 집 서버에서 하루 한 번(정해진 시각) 실행되고, 수동 실행도 된다.
- 로컬 LLM(학교 서버의 Qwen, HTTPS로 접속)을 호출하고, MCP 클라이언트로 서버들의 도구를 쓴다: Microsoft To Do, Gmail, GitHub, 폴리오(읽기), 카카오(전송). 벨루는 To Do로 대체할 예정이라 읽기 소스에서 제외한다.
- **일정 감지**: 읽기 소스에서 일정·마감·할 일 후보를 찾는다. 날짜를 지어내지 않고, 이미 있는 것은 만들지 않으며, 확실한 후보는 To Do에 태스크로 추가(마감이 불명확하면 마감 없는 태스크로)하고 브리핑에 알린다.
- **브리핑**: 구역 단위 말풍선(이전 시스템에서 확정한 규칙)과 "비서의 한마디"(어제와의 비교, 관찰, 제안, 질문)를 카톡 나에게 보내기로 보낸다. 어제 보고를 기억해서 이어서 말한다.
- **안전장치**: 쓰기는 To Do의 태스크 추가뿐이고 한 번의 실행에서 추가 개수 상한이 있다. 모델이나 도구가 실패해도 조용히 넘기지 않고, 모델 없이 To Do 목록만으로 만든 기본 브리핑과 실패 알림을 보낸다. 드라이런 모드는 아무것도 쓰거나 보내지 않는다.
- 이전 시스템과 **병행 운영해서 비교**한 뒤 퇴역한다.
- **범위 밖**: 입력 화면(To Do 앱을 쓴다), 대화로 답하는 챗봇, 음성·오디오, 태스크 수정·삭제·완료, 임베딩 기반 기억 검색(후속), 모델 학습.

## Capabilities

### New Capabilities
- `schedule-detection`: 읽기 소스에서 일정·마감·할 일 후보를 찾아 태스크로 추가하는 규칙과 안전장치.
- `daily-briefing`: 브리핑의 구성, 말풍선 나누기, 어제 기억, 실패 처리, 드라이런.

## Impact

- 새 코드: `agent/` (TypeScript). 의존하는 변경: `microsoft-todo-mcp`, `gmail-mcp`, `kakao-mcp`는 최소 필수이고 `github-mcp`, `folio-mcp`는 단계적으로 붙인다(`veloo-mcp`는 일일 브리핑에 쓰지 않고, 벨루 태스크를 To Do로 한 번 옮길 때만 쓴다).
- **선행 조건(사용자 작업)**: 학교 LLM을 HTTPS로 안정적으로 쓸 수 있어야 한다(방화벽 해결, 자체 서명 인증서 고정). 현재는 평문 `http://`와 임시 포트(3389)라서 에이전트의 본운영에는 쓰지 않는다. 집 서버에서 Node를 돌리고 하루 한 번 실행하는 환경도 필요하다.
- 위험: 로컬 모델의 도구 호출 정확도가 불확실하다. 그래서 가장 먼저 **측정용 시험(스파이크)** 을 하고 기준에 못 미치면 구조를 다시 정한다.
- 개인정보: 메일·GitHub·논문 내용이 학교 서버의 LLM으로 들어간다. 외부 상용 LLM으로는 보내지 않는다. 학교 서버 사용 규정은 사용자가 확인한다.
- 기존 Vercel 배포는 아직 돌고 있다(매일 아침 메일 선별, 벨루에 태스크 추가, 카톡 보고). 병행 기간에는 중복을 피하도록 정리가 필요하고, 비교가 끝나면 퇴역한다.
