# Spec Delta

## Purpose
읽기 소스(메일, GitHub, 폴리오)에서 일정과 마감과 할 일 후보를 찾아 To Do의 태스크로 추가하는 규칙과 안전장치를 정한다. 사람이 입력하지 않아도 일이 장부에 쌓이게 하면서, 모델의 실수가 중복·소음·엉뚱한 날짜로 번지지 않게 하는 것이 목적이다.

## ADDED Requirements

### Requirement: 날짜를 지어내지 않는다
시스템은 소스에 마감이 명확하게 적혀 있지 않으면 날짜를 추정해서 채우지 않아야 한다(SHALL NOT). 마감이 명확하지 않은 일은 마감을 비운 태스크로 추가해야 한다(SHALL). 날짜는 소스에 적힌 표현을 한국 표준시의 날짜로 바꾼 것이어야 하고, 달력 계산이 필요한 상대 표현은 도구가 준 현재 날짜를 기준으로 해야 한다(SHALL).

#### Scenario: 마감이 명확한 메일
- **WHEN** 메일 본문에 "제출 기한은 11월 30일까지"라고 적혀 있다
- **THEN** 마감이 11월 30일인 태스크 후보가 만들어진다

#### Scenario: 마감이 모호한 메일
- **WHEN** 메일에 해야 할 일은 있으나 마감 날짜가 없다
- **THEN** 마감이 비어 있는 태스크 후보가 만들어지고 날짜는 채워지지 않는다

### Requirement: 이미 있는 일은 만들지 않는다
시스템은 같은 이름과 같은 마감의 미완료 태스크가 이미 있으면 만들지 않아야 한다(SHALL NOT). 같은 메일 스레드에서 나온 마감 없는 일들은 하나의 태스크로 합쳐야 한다(SHALL). 이미 처리한 소스(메일, 이슈)를 기록해서 같은 소스를 다음 실행에서 다시 처리하지 않아야 한다(SHALL).

#### Scenario: 어제 만든 일
- **WHEN** 어제 추가한 태스크와 같은 이름·마감의 후보가 오늘 다시 나온다
- **THEN** 새로 만들지 않고 이미 있다고 기록한다

#### Scenario: 같은 스레드의 여러 일
- **WHEN** 한 스레드에서 마감 없는 일이 세 개 나온다
- **THEN** 태스크는 하나만 만들어진다

#### Scenario: 처리한 메일
- **WHEN** 이미 처리한 메일이 다음 실행의 검색에 다시 잡힌다
- **THEN** 다시 해석하지 않고 건너뛴다

### Requirement: 쓰기는 태스크 추가로만 하고 개수에 상한을 둔다
시스템은 태스크 추가 외의 쓰기(수정, 완료, 삭제, 메일·이슈 변경)를 하지 않아야 한다(SHALL NOT). 한 번의 실행에서 추가할 수 있는 태스크 수에는 상한이 있어야 하고(SHALL), 상한을 넘으면 넘는 후보는 추가하지 않고 브리핑에 알려야 한다(SHALL).

#### Scenario: 상한 이내
- **WHEN** 후보가 세 건이고 상한이 열 건이다
- **THEN** 세 건이 모두 추가된다

#### Scenario: 상한 초과
- **WHEN** 후보가 열두 건이고 상한이 열 건이다
- **THEN** 열 건만 추가되고 나머지 두 건은 추가되지 않았다는 알림이 브리핑에 들어간다

### Requirement: 추가한 태스크에 사람이 읽을 수 있는 출처를 남긴다
시스템은 추가하는 태스크의 본문에 출처(예: 메일 제목, 이슈 주소)와 마감 확인이 필요한지 여부를 사람이 읽을 수 있는 문장으로 남겨야 한다(SHALL). 시스템 내부용 표식이나 일련번호는 태스크 본문에 쓰지 않아야 한다(SHALL NOT).

#### Scenario: 메일에서 만든 태스크
- **WHEN** 메일에서 태스크를 만든다
- **THEN** 본문에 "메일: <원래 제목>"이 적혀 있다

#### Scenario: 내부 표식이 없음
- **WHEN** 추가된 태스크의 본문을 확인한다
- **THEN** 기계가 읽는 표식이나 번호 문자열이 없다

### Requirement: 소스의 내용을 로컬 모델에만 보낸다
시스템은 메일, 이슈, 논문, 태스크의 내용을 학교 서버의 로컬 모델과 로컬 로그에만 보내고 외부 상용 LLM 서비스로 보내지 않아야 한다(SHALL NOT). 로그에는 건수와 소요 시간 같은 값만 남기고 내용은 남기지 않아야 한다(SHALL).

#### Scenario: 모델 호출 대상
- **WHEN** 실행 중의 모든 모델 호출 대상을 확인한다
- **THEN** 설정된 로컬 모델 주소뿐이다

#### Scenario: 로그 내용
- **WHEN** 실행 뒤 로그를 확인한다
- **THEN** 메일 제목, 본문, 태스크 이름이 없다
