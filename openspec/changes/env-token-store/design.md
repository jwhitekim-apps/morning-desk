# Design

## Context

토큰 저장 방식은 서버마다 다르다(관찰한 코드 기준).
- To Do: MSAL의 캐시 플러그인이 `~/.config/microsoft-todo-mcp/token-cache.json`(약 5.7KB JSON)을 읽고, 바뀌었을 때(`cacheHasChanged`) 통째로 다시 쓴다. 위치는 `MS_TODO_TOKEN_CACHE`(파일 경로)로 바꿀 수 있다. CLI의 `login`·`logout`·`whoami`도 이 파일을 쓴다.
- Gmail: `TokenStore`가 `token.json`에 리프레시 토큰, 액세스 토큰, 만료 시각, 권한을 쓴다. OAuth 클라이언트는 환경 변수 또는 `client.json`에서 읽는다. CLI `login`·`logout`이 있다.
- 카카오: `TokenStore`가 `token.json`에 리프레시·액세스 토큰을 쓰고, 환경 변수 `KAKAO_REFRESH_TOKEN`은 파일이 없을 때의 시작 값이다.
- 벨루: `SessionStore`가 `session.json`에 세션 쿠키를 쓴다.

비서는 각 서버를 자식 프로세스로 띄우며 그 서버에 필요한 환경 변수만 넘긴다. 토큰이 실제로 바뀌는 곳은 To Do(갱신할 때마다 캐시가 바뀜), 카카오(드물게 새 리프레시 토큰), 벨루(로그인할 때), Gmail(로그인할 때)이다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**
- 토큰을 쓰는 곳이 `.env.local` 하나가 되고, 서버들이 함께 고쳐 써도 다른 줄을 잃지 않는다.
- 사람이 정리해 둔 `.env.local`의 모양(그룹, 주석, 순서)이 유지된다.
- 기존 동작(갱신, 재로그인, 오류 분류)은 그대로다.

**Non-Goals:**
- 비밀값 암호화, 비밀 관리 서비스.
- 여러 컴퓨터 사이의 토큰 동기화(맥북과 집 서버는 각자의 `.env.local`을 가진다).
- 비서의 기억 파일 이동.

## Decisions

### 1. 서버는 시작할 때의 환경 변수가 아니라 파일에서 직접 읽는다
비서가 `.env.local`을 읽어 환경 변수로 넘기는 값은 시작 시점의 스냅숏이다. 같은 실행 안에서 다른 서버가 파일을 고쳐 쓸 수 있고, 다음 실행에서는 파일이 기준이다. 그래서 토큰 키는 환경 변수로 넘기지 않고, 서버가 필요할 때 파일에서 그 키를 읽는다. 키가 정해지지 않은 다른 설정(클라이언트 ID 등)은 지금처럼 환경 변수로 받는다.

### 2. 공통 모듈은 서버마다 같은 파일을 두고, 같은지 테스트로 지킨다
서버들은 독립 패키지(각자 `npm ci`, 각자 빌드)라 공용 패키지를 두면 빌드 도구와 링크 설정이 복잡해진다. 그래서 약 100줄짜리 `env-file.ts`를 네 서버에 같은 내용으로 두고, "네 파일이 바이트 단위로 같다"는 테스트를 한 서버(To Do)에 둔다. 한쪽만 고치면 테스트가 실패한다. 모듈은 생성할 때 그 서버가 다룰 키 목록을 받고, 목록 밖의 키를 읽거나 쓰려 하면 파일을 열기 전에 오류를 낸다.

### 3. 쓰기는 잠금 → 다시 읽기 → 한 줄 교체 → 임시 파일 → 바꿔치기
1. 잠금 파일(`.env.local.lock`)을 배타적으로 만든다(`O_EXCL`). 이미 있으면 짧게 기다리며 다시 시도하고(최대 5초), 30초보다 오래된 잠금은 죽은 프로세스의 것으로 보고 지운다.
2. 잠근 상태에서 파일을 다시 읽는다(그 사이 다른 서버가 바꿨을 수 있으므로).
3. 그 키의 줄만 바꾼다. 같은 키가 여러 줄이면 첫 줄을 바꾸고 나머지는 지운다(값이 둘이면 어느 것이 맞는지 모호하므로). 없으면 파일 끝의 `# --- 토큰 (자동 갱신, 직접 고치지 마세요)` 구역에 더한다(구역이 없으면 만든다). 다른 줄은 원래 바이트 그대로 둔다(줄바꿈 문자 포함).
4. 같은 폴더의 임시 파일에 권한 600으로 쓰고 `rename`으로 바꿔치기한 뒤 잠금을 푼다.
값을 읽을 때는 잠그지 않는다(`rename`은 원자적이라 읽는 쪽은 항상 완전한 파일을 본다).

### 4. 값은 한 줄로 저장한다
리프레시 토큰과 세션 쿠키는 그대로 쓴다. To Do 캐시(여러 줄 JSON)는 base64로 바꿔 한 줄로 쓴다. 값에 줄바꿈이 들어가면 쓰지 않고 오류를 낸다. 따옴표는 쓰지 않는다(비서의 `.env` 읽기와 같은 규칙).

### 5. 파일 위치
`MY_TASK_ENV_FILE`(절대 경로)을 우선한다. 없으면 서버가 실행되는 파일(`mcp/<서버>/dist/index.js`)에서 세 단계 위의 저장소 루트를 찾아 `.env.local`을 쓴다. 비서는 저장소 루트의 `.env.local` 경로를 이 변수로 모든 서버에 넘긴다.

### 6. 서버별 키와 동작
| 서버 | 키 | 언제 쓰나 |
|---|---|---|
| To Do | `MS_TODO_TOKEN_CACHE_DATA` | MSAL 캐시가 바뀌었을 때. `logout`은 이 줄을 지운다 |
| Gmail | `GMAIL_REFRESH_TOKEN` | `login`에서. 액세스 토큰은 실행 중 메모리에만 둔다(하루 한 번 실행이라 다음 실행에서는 어차피 만료되어 있다). 권한 범위는 로그인 때 확인한 그대로 쓴다 |
| 카카오 | `KAKAO_REFRESH_TOKEN` | 갱신 응답에 새 리프레시 토큰이 왔을 때. 액세스 토큰은 메모리에만 |
| 벨루 | `VELOO_SESSION` | 로그인했을 때. 세션이 거부되면 줄을 지운다 |

Gmail의 `client.json`은 읽지 않는다(`GMAIL_CLIENT_ID`·`GMAIL_CLIENT_SECRET`만 쓴다).

### 7. 옮기기 명령은 비서에 둔다
`my-task-agent migrate-tokens`는 알려진 옛 위치(`~/.config/microsoft-todo-mcp/`, `~/.config/my-task-*-mcp/`, 그리고 맥북에서 임시로 모아 둔 `~/.config/my-task/*/`)에서 토큰 파일을 찾는다. 먼저 `.env.local`을 `.env.local.backup-<날짜>`(600)로 복사한 뒤 3번의 규칙으로 키를 쓰고, 다시 읽어 원래 값과 같으면 원래 파일과 빈 폴더를 지운다. `--dry-run`이면 찾은 파일과 쓸 키 이름만 보여 준다. 값은 출력하지 않는다.

### 8. 최소 권한은 코드로 대신한다
지금은 비서가 서버마다 자기 환경 변수만 넘겨서 다른 서버의 비밀을 볼 수 없다. 같은 파일을 쓰게 되면 운영체제 수준에서는 모든 서버가 파일 전체를 읽을 수 있다. 이 차이를 코드로 줄인다: 모듈이 자기 키만 꺼내고, 나머지 줄은 문자열로만 다루며 해석하지 않는다. 테스트가 "다른 키를 요청하면 오류"를 지킨다. 비서는 지금처럼 토큰이 아닌 설정만 환경 변수로 넘긴다.

## Risks / Trade-offs

- **공유 파일이 깨지면 모든 비밀을 잃는다.** 잠금, 다시 읽기, 원자적 교체, 옮기기 전 백업으로 막는다. 테스트에서 여러 프로세스가 동시에 쓰는 경우를 실제 자식 프로세스로 시험한다.
- **최소 권한이 약해진다**(결정 8). 사용자가 한 파일 관리를 원해서 받아들이는 대가다.
- **사람이 손으로 고치는 중에 서버가 쓰면** 편집기가 저장할 때 서버의 변경을 덮을 수 있다. 토큰 구역에 "직접 고치지 마세요" 주석을 두고 README에 적는다.
- **To Do 캐시가 한 줄에 약 7.7KB**라 파일이 보기 불편해진다. 맨 끝 토큰 구역에 모아서 위쪽의 정리된 설정과 섞이지 않게 한다.
- **맥북과 집 서버가 같은 토큰으로 각자 갱신하면** 한쪽 토큰이 무효가 될 수 있다(지금도 같은 위험). 집 서버로 옮긴 뒤에는 맥북에서 비서를 돌리지 않는다.
