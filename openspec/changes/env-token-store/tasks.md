# Tasks

## 1. 공통 모듈

- [ ] 1.1 `env-file.ts`를 To Do 서버에 만든다: 정해진 키 목록만 허용, 한 키 읽기, 한 키 쓰기와 지우기(잠금 → 다시 읽기 → 한 줄 교체 또는 토큰 구역에 추가 → 임시 파일 600 → 바꿔치기), 오래된 잠금 정리, 위치 결정(`MY_TASK_ENV_FILE`, 없으면 저장소 루트의 `.env.local`), 값이 들어가지 않는 오류 메시지. 검증: 테스트에서 다른 줄·주석·빈 줄·순서가 바이트 그대로 남고, 같은 키가 둘이면 하나로 정리되며, 목록 밖 키는 파일을 열기 전에 오류가 나고, 쓴 뒤 권한이 600이며, 오류에 값이 없다
- [ ] 1.2 여러 프로세스가 동시에 쓰는 시험을 실제 자식 프로세스로 만든다. 검증: 두 프로세스가 각자 다른 키를 100번씩 번갈아 써도 끝난 뒤 두 키가 모두 마지막 값이고 다른 줄은 그대로다. 쓰는 도중 프로세스를 죽여도 파일이 완전한 이전 내용이나 새 내용이다
- [ ] 1.3 같은 `env-file.ts`를 Gmail, 카카오, 벨루 서버에 두고, 네 파일이 같은지 확인하는 테스트를 To Do 서버에 둔다. 검증: 한 파일만 고치면 테스트가 실패한다

## 2. 서버별 저장소 교체

- [ ] 2.1 To Do: MSAL 캐시 플러그인이 `.env.local`의 `MS_TODO_TOKEN_CACHE_DATA`(base64 한 줄)를 읽고 쓰게 바꾸고, `logout`은 그 줄을 지우게 한다. 홈 폴더 토큰 경로 설정은 없앤다. 검증: 테스트에서 캐시가 바뀌면 그 줄만 바뀌고, 다시 읽으면 같은 캐시이며, 깨진 값은 빈 캐시로 시작하고, 로그와 응답에 값이 없다
- [ ] 2.2 Gmail: 리프레시 토큰을 `GMAIL_REFRESH_TOKEN`에 쓰고 읽게 하고, 액세스 토큰은 메모리에만 둔다. OAuth 클라이언트는 `GMAIL_CLIENT_ID`·`GMAIL_CLIENT_SECRET`만 쓴다(`client.json` 제거). `login`·`logout`도 바꾼다. 검증: 기존 인증 테스트(읽기 전용 권한, 갱신, 폐기된 토큰은 다시 로그인 안내)가 새 저장소로 모두 통과하고, 홈 폴더에 파일이 생기지 않는다
- [ ] 2.3 카카오: 갱신 응답의 새 리프레시 토큰을 `KAKAO_REFRESH_TOKEN` 줄에 고쳐 쓰고, 액세스 토큰은 메모리에만 둔다. 검증: 새 리프레시 토큰이 오면 그 줄이 바뀌어 다음 실행에서 쓰이고, 안 오면 줄이 바뀌지 않으며, 만료된 리프레시 토큰은 다시 로그인 안내가 된다
- [ ] 2.4 벨루: 세션을 `VELOO_SESSION`에 쓰고 읽게 하고, 세션이 거부되면 줄을 지운다. 검증: 기존 세션 테스트(재사용, 한 번만 재로그인, 로그인 실패 시 15분 쉼)가 새 저장소로 모두 통과한다

## 3. 비서

- [ ] 3.1 비서가 모든 서버에 `MY_TASK_ENV_FILE`(저장소 루트의 `.env.local` 절대 경로)을 넘기고, 토큰 폴더 변수(`MS_TODO_TOKEN_CACHE`, `GMAIL_MCP_DIR`, `KAKAO_MCP_DIR`)와 `KAKAO_REFRESH_TOKEN`은 넘기지 않게 한다. 검증: 설정 테스트에서 모든 서버가 그 경로를 받고, 토큰 값은 어떤 서버의 환경 변수에도 없다
- [ ] 3.2 `migrate-tokens` 명령을 만든다(옛 위치 찾기, `.env.local` 백업 600, 키 쓰기, 다시 읽어 확인, 확인된 원래 파일과 빈 폴더 삭제, `--dry-run`). 검증: 임시 홈 폴더 테스트에서 네 종류가 옮겨지고 원래 파일이 지워지며, 일부가 없으면 건너뛰었다고 알리고, 확인이 실패하면 원래 파일을 지우지 않고, 출력에 값이 없다

## 4. 보호 테스트

- [ ] 4.1 서버마다 모든 도구를 실행한 뒤 로그와 응답에 `.env.local`의 어떤 값도 없는지, 실행 후 다른 서버의 키와 정리된 설정 줄이 그대로인지 확인하는 테스트를 만든다. 검증: 일부러 값을 로그에 넣거나 다른 줄을 바꾸면 테스트가 실패한다
- [ ] 4.2 `.env.local`, 백업 파일, 잠금 파일, 임시 파일이 git에서 제외되는지 확인한다. 검증: `git check-ignore`가 네 이름 모두를 제외 대상으로 알린다

## 5. 문서

- [ ] 5.1 네 서버의 README와 루트 문서(`AGENTS.md`)에 토큰 위치(`.env.local`의 키 이름), 토큰 구역은 손으로 고치지 말 것, 옮기기 명령을 적는다. 검증: README에 홈 폴더 토큰 경로가 더는 나오지 않는다

## 6. 실제 적용 (사용자와 함께)

- [ ] 6.1 맥북에서 `migrate-tokens --dry-run`으로 확인한 뒤 실제로 옮기고, 비서 드라이런으로 To Do·Gmail·카카오가 정상인지 본다(보내지 않음). 검증: 드라이런이 실패 없이 끝나고, `~/.config/my-task*`와 `~/.config/microsoft-todo-mcp`에 토큰 파일이 없으며, `.env.local` 권한이 600이다
- [ ] 6.2 집 서버에 코드를 다시 복사·빌드하고 `migrate-tokens`를 실행한 뒤 드라이런으로 확인한다. 다음 아침 7시 실행 결과를 기록에서 확인한다. 검증: 드라이런이 실패 없이 끝나고, 다음 날 아침 브리핑이 도착하며, 서버의 옛 토큰 폴더가 없다
