# Design

## Context

폴리오는 Zotero 논문 뷰어 웹앱이고 논문 목록이 Supabase의 `folio_papers`(`item_key`, `title`, `year`, `synced_at`)에 동기화된다. 이전 시스템은 서비스 키(관리자 권한)로 이 테이블을 PostgREST로 읽었다. `synced_at`은 정보를 다시 가져올 때마다 바뀌므로 "처음 저장한 시각"이 아니라서, 새 논문 판단은 읽는 쪽이 따로 "처음 본 시점"을 기록해야 했다. 동기는 proposal.md의 Why를 본다.

## Goals / Non-Goals

**Goals:**
- 폴리오를 바꾸지 않고 논문 목록과 제목 검색을 읽기만 한다.
- 읽는 키가 관리자 권한이 아니도록 한다.

**Non-Goals:**
- 새 논문 판단, 의미 검색, 폴리오 스키마 변경, 쓰기.

## Decisions

### 1. 의존성 없이 PostgREST를 직접 부른다
조회 두 가지뿐이라서 Supabase 클라이언트 라이브러리를 쓰지 않고 표준 `fetch`로 부른다. 의존성이 없으면 점검할 코드와 취약점 경고가 줄어든다. 요청은 항상 GET이다.

### 2. 키 방침은 사용자의 결정이 필요하다
선택지는 세 가지다. (a) 서비스 키: 간단하지만 관리자 권한이라 서버가 뚫리면 폴리오 데이터 전체에 닿는다. (b) 읽기 전용 역할의 키와 행 수준 보안 정책: 안전하지만 폴리오 쪽 Supabase 설정을 바꿔야 한다. (c) 읽기 전용 뷰: `folio_papers`의 필요한 컬럼만 노출하는 뷰를 만들고 그 뷰만 읽는 키를 쓴다. 이 서버는 키 종류에 무관하게 동작하게 만들고, 시험 단계에서는 (a)를 허용하되 **운영 전에 (b)나 (c)로 교체**한다. 폴리오가 쓰는 Supabase 프로젝트의 설정 변경은 사용자 확인 후에 한다.

### 3. 제목 검색은 검색어를 이스케이프한다
`ilike` 조건에 `%`, `*`, `,`, `)` 같은 글자가 들어가면 조회 조건이 깨지거나 의도치 않게 넓어진다. 검색어를 안전하게 인코딩하고 와일드카드 문자는 글자 그대로 찾도록 처리한다.

### 4. 시각의 의미를 응답에 밝힌다
도구 설명과 응답 필드 이름을 `syncedAt`으로 하고, 처음 저장한 시각이 아니라는 설명을 붙인다. 모델이 이 값을 "새 논문"의 근거로 단독 사용하지 않게 한다.

### 5. 개수 상한과 잘림 표시
기본 상한을 두고(예: 200, 최대 500) 상한에 걸리면 잘림 표시를 한다. 이전에는 500편을 가져오고 말없이 넘겼다.

## Risks / Trade-offs

- **서비스 키를 계속 쓰면 위험이 남는다.** 결정 2의 교체를 완료 기준에 넣는다.
- **`synced_at`만으로는 새 논문을 정확히 알 수 없다.** 폴리오에 `created_at`을 추가하는 것이 정석이지만 폴리오 프로젝트의 변경이라 이 변경 밖이다. 그동안은 에이전트가 "처음 본 시점"을 기록한다.
- **테이블 구조가 바뀌면 깨진다.** 필수 필드 검사로 알아채고 구분된 오류로 알린다.
