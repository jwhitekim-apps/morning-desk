# Spec Delta

## Purpose
에이전트가 폴리오의 논문 목록을 읽기 전용으로 조회하고 제목으로 찾는 MCP 도구의 계약을 정한다. 폴리오의 코드와 데이터를 바꾸지 않고 읽기만 해서, 논문 흐름을 브리핑에 반영하는 데 필요한 재료를 안전하게 주는 것이 목적이다.

## ADDED Requirements

### Requirement: 읽기만 하고 쓰기 요청을 보내지 않는다
시스템은 폴리오 데이터베이스에 조회 요청만 보내야 한다(SHALL). 삽입, 수정, 삭제 요청을 보내는 도구를 제공하지 않아야 한다(SHALL NOT). 도구 목록은 허용 목록과 정확히 같아야 한다(SHALL).

#### Scenario: 허용된 도구만 있음
- **WHEN** 서버의 도구 목록을 조회한다
- **THEN** 허용 목록과 정확히 일치하고 쓰기 이름의 도구가 없다

#### Scenario: 조회 요청만 나감
- **WHEN** 모든 도구를 한 번씩 실행하고 나간 요청을 확인한다
- **THEN** 모두 조회(GET)이고 데이터를 바꾸는 요청이 없다

### Requirement: 최근 논문 목록을 조회한다
시스템은 개수와 기준 시각을 받아 그 이후에 동기화된 논문을 동기화 시각 최신순으로 돌려주어야 한다(SHALL). 각 논문에는 항목 번호, 제목, 연도, 동기화 시각이 포함되어야 한다(SHALL). 제목이 비어 있으면 "(제목 없음)"으로 표시해야 한다(SHALL). 결과가 개수 상한에 걸려 잘렸으면 잘렸다는 사실을 알려야 한다(SHALL).

#### Scenario: 최근 일주일
- **WHEN** 기준 시각을 일주일 전으로 조회한다
- **THEN** 그 이후에 동기화된 논문이 최신순으로 나온다

#### Scenario: 제목이 없는 항목
- **WHEN** 제목이 비어 있는 논문이 있다
- **THEN** "(제목 없음)"으로 표시된다

#### Scenario: 개수 상한
- **WHEN** 조건에 맞는 논문이 상한보다 많다
- **THEN** 상한까지만 돌려주고 잘렸다는 표시를 함께 준다

### Requirement: 제목으로 논문을 찾는다
시스템은 검색어를 받아 제목에 그 글자가 들어 있는 논문을 대소문자 구분 없이 돌려주어야 한다(SHALL). 검색어에 들어 있는 특수문자가 조회 조건을 깨뜨리지 않아야 한다(SHALL).

#### Scenario: 부분 일치
- **WHEN** "attention"으로 검색한다
- **THEN** 제목에 "Attention"이 들어 있는 논문이 나온다

#### Scenario: 특수문자가 든 검색어
- **WHEN** 검색어에 `%`, `*`, `,`, `)` 같은 글자가 들어 있다
- **THEN** 오류가 나지 않고 그 글자를 그대로 포함한 제목만 찾는다

### Requirement: 동기화 시각의 한계를 응답에 밝힌다
시스템은 논문의 시각 정보가 "동기화 시각"이며 처음 저장한 시각이 아니라는 사실을 도구 설명과 응답에 밝혀야 한다(SHALL). 동기화 시각은 다시 가져올 때마다 바뀔 수 있으므로 새 논문이라는 판단의 근거로 단독 사용하지 않도록 안내해야 한다(SHALL).

#### Scenario: 도구 설명
- **WHEN** 목록 조회 도구의 설명을 읽는다
- **THEN** 시각이 동기화 시각이고 새 논문 판단에는 부족하다는 안내가 있다

### Requirement: 키를 보호하고 오류를 구분해서 알린다
시스템은 접속 키를 도구 응답과 로그에 남기지 않아야 한다(SHALL NOT). 키가 틀림(인증 오류), 테이블이 없음, 서버 일시 장애를 구분된 오류로 알려야 한다(SHALL). 접속 키는 읽기 전용으로 제한된 키를 쓰는 것을 원칙으로 한다(SHALL).

#### Scenario: 인증 오류
- **WHEN** 키가 틀려 서버가 거부한다
- **THEN** 인증 오류로 구분해서 알리고 키 값을 출력하지 않는다

#### Scenario: 테이블이 없음
- **WHEN** 논문 테이블을 찾을 수 없다
- **THEN** 테이블이 없다는 오류로 인증 오류와 구분해서 알린다
