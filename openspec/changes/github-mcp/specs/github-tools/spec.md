# Spec Delta

## Purpose
에이전트가 내게 해당하는 GitHub 일(리뷰 요청, 배정된 이슈와 PR, 마일스톤 마감, 알림)을 읽기 전용으로 조회하는 MCP 도구의 계약을 정한다. 쓰기와 코드 읽기를 주지 않아서, 모델이 잘못 판단해도 저장소가 바뀌지 않게 하는 것이 목적이다.

## ADDED Requirements

### Requirement: 읽기 전용으로만 접근한다
시스템은 읽기 권한만 가진 인증으로 GitHub에 접근해야 한다(SHALL). 코멘트, 이슈·PR 생성과 수정, 머지, 푸시, 리뷰 제출 같은 쓰기 도구를 제공하지 않아야 한다(SHALL NOT). 도구 목록은 허용 목록과 정확히 같아야 하며, 새 도구를 추가하려면 그 목록을 의도적으로 고쳐야 한다(SHALL).

#### Scenario: 허용된 도구만 있음
- **WHEN** 서버의 도구 목록을 조회한다
- **THEN** 허용 목록과 정확히 일치하고 쓰기 이름의 도구가 없다

#### Scenario: 읽기 전용 설정이 실제로 쓰기 도구를 숨김
- **WHEN** 기존 서버를 쓰는 경우 읽기 전용 설정으로 시작하고 도구 목록을 확인한다
- **THEN** 쓰기에 해당하는 도구가 하나도 노출되지 않는다

### Requirement: 내게 온 리뷰 요청을 조회한다
시스템은 내게 리뷰가 요청된 열린 PR의 목록을 돌려주어야 한다(SHALL). 각 항목에는 저장소, 번호, 제목, 주소, 마지막 갱신 시각, 요청한 사람이 포함되어야 한다(SHALL).

#### Scenario: 리뷰 요청이 있음
- **WHEN** 내게 리뷰가 요청된 PR이 두 개 있다
- **THEN** 두 PR이 저장소, 제목, 주소와 함께 갱신이 이른 것부터 나온다

#### Scenario: 요청이 없음
- **WHEN** 리뷰 요청이 없다
- **THEN** 빈 목록을 오류 없이 돌려준다

### Requirement: 내게 배정된 이슈와 PR을 마일스톤 마감과 함께 조회한다
시스템은 내게 배정된 열린 이슈와 PR을 돌려주어야 한다(SHALL). 마일스톤이 있으면 그 마감일을 함께 돌려주어야 한다(SHALL). 마감일이 없는 항목도 포함하되 마감이 없다고 표시해야 한다(SHALL).

#### Scenario: 마일스톤이 있는 이슈
- **WHEN** 마일스톤 마감이 있는 이슈가 배정되어 있다
- **THEN** 이슈 정보와 함께 그 마감 날짜가 나온다

#### Scenario: 마일스톤이 없는 이슈
- **WHEN** 마일스톤이 없는 이슈가 배정되어 있다
- **THEN** 결과에 포함되고 마감은 없음으로 표시된다

### Requirement: 읽지 않은 알림을 조회한다
시스템은 읽지 않은 알림의 목록을 돌려주어야 한다(SHALL). 조회가 알림을 읽음으로 표시하지 않아야 한다(SHALL NOT).

#### Scenario: 알림을 읽어도 상태가 그대로
- **WHEN** 알림을 두 번 연달아 조회한다
- **THEN** 두 번 모두 같은 목록이 나온다

### Requirement: 결과 개수를 제한하고 토큰을 보호한다
시스템은 결과를 개수 상한까지만 돌려주고 잘렸으면 알려야 한다(SHALL). 인증 토큰은 도구 응답과 로그에 나타나지 않아야 한다(SHALL NOT). 인증 실패, 권한 부족, 요청 한도 초과를 구분된 오류로 알려야 한다(SHALL).

#### Scenario: 상한을 넘는 결과
- **WHEN** 조건에 맞는 항목이 상한보다 많다
- **THEN** 상한까지만 돌려주고 잘렸다는 표시를 함께 준다

#### Scenario: 요청 한도 초과
- **WHEN** GitHub가 요청 한도를 초과했다고 응답한다
- **THEN** 요청 한도 초과 오류와 다시 시도할 수 있는 시각을 알린다
