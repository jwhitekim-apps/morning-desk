# Proposal

## Why

일정과 마감이 적힌 메일은 비서가 사람의 입력 없이 감지할 수 있는 가장 큰 소스다. 이전 시스템(`veloo-secretary`)에서 Gmail을 읽기 전용으로 키워드 검색하고 중요한 메일의 본문을 읽는 어댑터가 실제로 동작했고(쓰기 시도는 403으로 거부되는 것까지 확인), 후속 메일을 원본 스레드의 제목으로 묶는 처리도 필요하다는 것을 배웠다. 이번에는 그 능력을 에이전트가 쓰는 **MCP 서버**로 분리한다. 판단(중요한 메일인지, 마감이 무엇인지)은 에이전트의 일이고, 이 서버는 안전하게 읽어서 돌려주는 데만 책임을 진다.

## What Changes

- `mcp/gmail/`에 **Gmail 읽기 전용 MCP 서버**를 만든다: 메일 검색(검색식, 기간, 개수), 메일 본문 읽기(길이 상한, 잘림 표시), 스레드 첫 메일 제목 제공.
- 인증은 Google OAuth(`gmail.readonly` 권한 하나), 토큰은 사용자 홈 아래 파일 권한 600으로 보관한다.
- 도구 표면은 읽기 도구로 고정하고 허용 목록 테스트가 지킨다. 보내기, 삭제, 보관, 라벨 변경 도구는 만들지 않는다.
- 가장 먼저 **기존 Gmail MCP 서버를 조사**해서 채택, 일부 가져오기, 직접 작성 중 고른다(Microsoft To Do 서버와 같은 방식, 출처는 반드시 표시).
- **범위 밖**: 키워드 선별과 중요도 판단, 마감 추출(에이전트), 첨부파일, 메일 보내기와 수정, 다른 메일 서비스.

## Impact

- 새 코드: `mcp/gmail/` (TypeScript, Node 20 이상, 표준입출력 MCP 서버).
- 외부 시스템: Gmail API. 이전에 만든 Google Cloud OAuth 클라이언트를 다시 쓸 수 있는지 확인이 필요하다.
- 알려진 위험: OAuth 동의 화면이 "테스트" 상태이면 갱신 토큰이 7일 뒤 만료될 수 있다(이전 운영 문서에 기록됨). 개인용으로 "프로덕션 게시"로 바꾸는 방법을 검토해야 한다.
- 개인정보: 메일 본문은 로컬 LLM으로만 흘러가고 외부 LLM으로 보내지 않는다는 전제를 에이전트 변경(`assistant-app`)이 지킨다. 이 서버는 본문을 로그에 남기지 않는다.
