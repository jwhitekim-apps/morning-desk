# Spec Delta

## Purpose
에이전트가 Microsoft To Do의 태스크를 읽고 새 태스크를 추가하는 MCP 도구의 계약을 정한다. 읽기와 추가만 허용하고 수정·완료·삭제는 도구로 주지 않아서, 모델이 잘못 판단해도 되돌릴 수 없는 피해가 생기지 않게 하는 것이 목적이다.

## ADDED Requirements

### Requirement: 기기 코드 방식으로 로그인하고 토큰을 안전하게 보관한다
시스템은 브라우저에서 코드를 입력하는 기기 코드 방식으로 로그인해야 한다(SHALL). 로그인 토큰은 사용자 홈 폴더 아래에 폴더 권한 700, 파일 권한 600으로 저장해야 한다(SHALL). 토큰과 비밀값은 도구 응답과 로그에 나타나지 않아야 한다(SHALL NOT).

#### Scenario: 처음 로그인
- **WHEN** 로그인 도구를 호출한다
- **THEN** 웹 주소와 입력할 코드를 돌려주고, 사용자가 브라우저에서 입력을 마치면 로그인 상태가 된다

#### Scenario: 이미 로그인되어 있음
- **WHEN** 저장된 유효한 토큰이 있는 상태에서 로그인 상태를 확인한다
- **THEN** 다시 로그인을 요구하지 않고 로그인된 계정이 있음을 알린다

#### Scenario: 토큰 만료
- **WHEN** 액세스 토큰이 만료되었지만 갱신할 수 있다
- **THEN** 사용자에게 묻지 않고 갱신하며, 갱신할 수 없으면 다시 로그인이 필요하다고 알린다

#### Scenario: 출력에 토큰이 없음
- **WHEN** 어떤 도구를 호출하든 응답과 로그를 확인한다
- **THEN** 액세스 토큰, 갱신 토큰, 비밀값이 포함되어 있지 않다

### Requirement: 요청하는 권한을 최소로 한다
시스템은 기본으로 태스크 읽기·쓰기 권한 하나만 요청해야 한다(SHALL). 읽기 전용 권한 설정이 켜져 있으면 읽기 권한만 요청해야 한다(SHALL). 읽기 전용 실행 설정이 켜져 있으면 쓰기 도구를 도구 목록에서 숨겨야 한다(SHALL).

#### Scenario: 기본 권한
- **WHEN** 기본 설정으로 로그인한다
- **THEN** 동의 화면에서 요청하는 태스크 권한은 읽기·쓰기 하나뿐이다

#### Scenario: 읽기 전용 권한
- **WHEN** 읽기 전용 권한 설정을 켜고 로그인한다
- **THEN** 요청하는 권한은 태스크 읽기뿐이다

#### Scenario: 읽기 전용 실행
- **WHEN** 읽기 전용 실행 설정을 켜고 서버를 시작한다
- **THEN** 도구 목록에 태스크 추가 도구가 나타나지 않는다

### Requirement: 도구는 읽기와 태스크 추가로 고정한다
시스템은 로그인 도구, 목록 조회, 태스크 조회, 마감 범위 조회, 태스크 추가 도구만 제공해야 한다(SHALL). 태스크 수정, 완료 처리, 삭제, 목록 생성·수정·삭제, 체크리스트 도구는 제공하지 않아야 한다(SHALL NOT). 도구 목록은 허용 목록과 정확히 같아야 하며, 새 도구를 추가하려면 그 허용 목록을 의도적으로 고쳐야 한다(SHALL).

#### Scenario: 허용된 도구만 있음
- **WHEN** 서버의 도구 목록을 조회한다
- **THEN** 허용 목록에 있는 도구와 정확히 일치한다

#### Scenario: 위험한 도구가 없음
- **WHEN** 도구 목록에서 위험 등급이 삭제인 도구나 수정·완료·삭제 이름의 도구를 찾는다
- **THEN** 하나도 없다

### Requirement: 같은 태스크를 중복으로 만들지 않는다
시스템은 같은 목록에 이름과 마감이 같은 미완료 태스크가 이미 있으면 새로 만들지 않고 이미 있는 태스크를 알려야 한다(SHALL). 같은 실행 안에서 같은 내용의 추가 요청이 짧은 시간 안에 다시 오면 처음 결과를 돌려주어야 한다(SHALL). 프로그램을 다시 시작해도 첫 번째 규칙은 지켜져야 한다(SHALL).

#### Scenario: 이미 있는 태스크
- **WHEN** 목록에 "랩미팅" 마감 10/13인 미완료 태스크가 있는 상태에서 같은 이름과 마감으로 추가를 요청한다
- **THEN** 새 태스크를 만들지 않고, 이미 있다는 사실과 기존 태스크를 돌려준다

#### Scenario: 같은 실행의 재시도
- **WHEN** 같은 내용의 추가 요청을 연달아 두 번 보낸다
- **THEN** 태스크는 하나만 생기고 두 번째는 처음 결과와 같다

#### Scenario: 프로그램을 다시 시작한 뒤의 재시도
- **WHEN** 서버를 다시 시작한 뒤 이미 만들어진 것과 같은 이름·마감으로 추가를 요청한다
- **THEN** 새 태스크를 만들지 않는다

#### Scenario: 이름이 같고 마감이 다름
- **WHEN** 이름은 같지만 마감이 다른 태스크를 추가한다
- **THEN** 별개의 태스크로 만든다

### Requirement: 마감 범위로 모든 목록의 미완료 태스크를 한 번에 조회한다
시스템은 시작 날짜와 끝 날짜를 받아 모든 목록에서 그 기간에 마감인 미완료 태스크를 마감 순으로 모아 목록 이름과 함께 돌려주는 도구를 제공해야 한다(SHALL). 선택하면 시작 날짜 이전에 마감이 지난 미완료 태스크도 함께 돌려주어야 한다(SHALL). 완료된 태스크와 마감이 없는 태스크는 포함하지 않아야 한다(SHALL NOT). 결과가 한도를 넘어 잘리면 잘렸다는 사실과 남은 개수를 알려야 한다(SHALL).

#### Scenario: 오늘부터 일주일
- **WHEN** 시작 날짜를 오늘, 끝 날짜를 7일 뒤로 조회한다
- **THEN** 모든 목록에서 그 기간에 마감인 미완료 태스크가 마감이 이른 순서로, 각각 속한 목록 이름과 함께 나온다

#### Scenario: 밀린 일 포함
- **WHEN** 밀린 일 포함 옵션을 켜고 조회한다
- **THEN** 시작 날짜보다 먼저 마감이 지난 미완료 태스크도 함께 나오고 밀린 것임을 구분할 수 있다

#### Scenario: 제외되는 것
- **WHEN** 마감이 없는 태스크와 완료된 태스크가 있는 상태에서 조회한다
- **THEN** 두 종류는 결과에 나오지 않는다

#### Scenario: 한도를 넘는 결과
- **WHEN** 조건에 맞는 태스크가 한도보다 많다
- **THEN** 한도까지만 돌려주고 잘렸다는 표시와 남은 개수를 함께 알린다

### Requirement: 마감과 알림 일시는 한국 표준시로 다룬다
시스템은 날짜만 주어진 마감은 한국 표준시의 그 날짜로, 시간대 없이 주어진 일시는 한국 표준시로 해석해야 한다(SHALL). 조회 결과의 마감과 알림 일시는 한국 표준시 기준의 날짜와 시각으로 보여 주어야 한다(SHALL). 서버가 다른 시간대로 돌려준 값도 한국 날짜로 변환해서 하루가 어긋나지 않아야 한다(SHALL).

#### Scenario: 한국 시간 자정 직후의 마감
- **WHEN** 한국 시간으로 10월 13일 00:30이 마감인 태스크를 조회한다(협정 세계시로는 10월 12일)
- **THEN** 마감 날짜는 10월 13일로 보이고, 10월 13일 하루를 조회할 때 포함된다

#### Scenario: 시간대 없는 일시 입력
- **WHEN** 시간대 표시 없이 "2026-10-13T15:00"으로 마감을 추가한다
- **THEN** 한국 시간 10월 13일 15:00으로 저장된다

#### Scenario: 날짜만 입력
- **WHEN** "2026-10-13"으로 마감을 추가한다
- **THEN** 한국 시간 10월 13일 마감으로 저장되고 앱에도 10월 13일로 보인다

### Requirement: 오류를 숨기지 않고 원인을 구분해서 알린다
시스템은 오류를 조용히 삼키지 않고 원인별로 구분된 코드와 메시지로 알려야 한다(SHALL). 구분은 로그인 필요, 로그인 만료, 권한 부족, 찾을 수 없음, 입력 오류, 요청 한도 초과, 서버 일시 장애를 포함해야 한다(SHALL). 요청 한도 초과일 때는 기다릴 시간을 알려야 한다(SHALL).

#### Scenario: 로그인 전 호출
- **WHEN** 로그인하지 않은 상태에서 태스크를 조회한다
- **THEN** 로그인이 필요하다는 오류 코드와, 로그인 도구를 쓰라는 안내를 돌려준다

#### Scenario: 읽기 전용으로 로그인한 뒤 추가 시도
- **WHEN** 읽기 권한만 받은 상태에서 태스크 추가를 요청한다
- **THEN** 권한이 부족하다는 오류를 돌려주고 아무것도 만들지 않는다

#### Scenario: 요청 한도 초과
- **WHEN** 서버가 요청이 너무 많다고 응답한다
- **THEN** 재시도 후에도 실패하면 요청 한도 초과 오류와 기다릴 시간을 알린다
