# Spec Delta

## MODIFIED Requirements

### Requirement: 읽기만 하고 쓰기 요청을 보내지 않는다
시스템은 폴리오 데이터베이스에 조회 요청만 보내야 한다(SHALL). 삽입, 수정, 삭제 요청을 보내는 동작을 앱에 내보내지 않아야 한다(SHALL NOT). 내보내는 동작(최근 논문, 제목 검색)의 목록은 허용 목록과 정확히 같아야 한다(SHALL).

#### Scenario: 허용된 도구만 있음
- **WHEN** 폴리오 모듈이 앱에 내보내는 동작의 이름을 모은다
- **THEN** 허용 목록과 정확히 일치하고 쓰기 이름의 동작이 없다

#### Scenario: 조회 요청만 나감
- **WHEN** 모든 동작을 한 번씩 실행하고 나간 요청을 확인한다
- **THEN** 모두 조회(GET)이고 데이터를 바꾸는 요청이 없다

### Requirement: 동기화 시각의 한계를 응답에 밝힌다
시스템은 논문의 시각 정보가 "동기화 시각"이며 처음 저장한 시각이 아니라는 사실을 모듈의 함수 설명과 응답에 밝혀야 한다(SHALL). 동기화 시각은 다시 가져올 때마다 바뀔 수 있으므로 새 논문이라는 판단의 근거로 단독 사용하지 않도록 안내해야 한다(SHALL).

#### Scenario: 도구 설명
- **WHEN** 목록 조회 함수의 설명(모듈 문서 주석)을 읽는다
- **THEN** 시각이 동기화 시각이고 새 논문 판단에는 부족하다는 안내가 있다

### Requirement: 키를 보호하고 오류를 구분해서 알린다
시스템은 접속 키를 결과, 오류 메시지, 로그에 남기지 않아야 한다(SHALL NOT). 키가 틀림(인증 오류), 테이블이 없음, 서버 일시 장애를 구분된 오류로 알려야 한다(SHALL). 접속 키는 저장소 루트의 `.env.local`(권한 600)에만 두어야 한다(SHALL). 읽기 전용으로 제한된 키 대신 전체 권한의 서비스 롤 키를 쓸 수 있다(MAY). 서비스 롤 키를 쓰면 앱이 조회만 한다는 사실이 유일한 안전장치이므로, 폴리오 모듈은 조회 외 요청을 보내지 않아야 한다(SHALL NOT).

#### Scenario: 인증 오류
- **WHEN** 키가 틀려 서버가 거부한다
- **THEN** 인증 오류로 구분해서 알리고 키 값을 출력하지 않는다

#### Scenario: 테이블이 없음
- **WHEN** 논문 테이블을 찾을 수 없다
- **THEN** 테이블이 없다는 오류로 인증 오류와 구분해서 알린다

#### Scenario: 서비스 롤 키로 사용
- **WHEN** 서비스 롤 키를 설정하고 폴리오 모듈의 모든 함수를 실행한다
- **THEN** 나가는 요청은 모두 조회(GET)이고, 결과와 로그에 키 값이 없다
