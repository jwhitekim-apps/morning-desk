# Spec Delta

## MODIFIED Requirements

### Requirement: 기기 코드 방식으로 로그인하고 토큰을 안전하게 보관한다
시스템은 브라우저에서 코드를 입력하는 기기 코드 방식으로 로그인해야 한다(SHALL). 로그인은 사람이 터미널에서 실행하는 앱의 로그인 명령으로 하며, 앱이 하루 실행 중에 로그인을 시작하지 않아야 한다(SHALL NOT). 로그인 토큰(토큰 캐시)은 저장소 루트의 `.env.local`(권한 600)에 `MS_TODO_TOKEN_CACHE_DATA` 키로 저장해야 한다(SHALL). 토큰과 비밀값은 결과, 오류 메시지, 로그에 나타나지 않아야 한다(SHALL NOT).

#### Scenario: 처음 로그인
- **WHEN** 사람이 앱의 To Do 로그인 명령을 실행한다
- **THEN** 웹 주소와 입력할 코드가 터미널에 나오고, 사용자가 브라우저에서 입력을 마치면 로그인 상태가 된다

#### Scenario: 이미 로그인되어 있음
- **WHEN** 저장된 유효한 토큰이 있는 상태에서 로그인 상태 확인 명령을 실행한다
- **THEN** 다시 로그인을 요구하지 않고 로그인된 계정을 알린다

#### Scenario: 토큰 만료
- **WHEN** 액세스 토큰이 만료되었지만 갱신할 수 있다
- **THEN** 사용자에게 묻지 않고 갱신하며, 갱신할 수 없으면 다시 로그인이 필요하다고 알린다

#### Scenario: 출력에 토큰이 없음
- **WHEN** 어떤 동작을 실행하든 결과와 로그를 확인한다
- **THEN** 액세스 토큰, 갱신 토큰, 비밀값이 포함되어 있지 않다

#### Scenario: 토큰이 .env.local에 저장됨
- **WHEN** 로그인하거나 토큰이 갱신된 뒤 `.env.local`을 확인한다
- **THEN** `MS_TODO_TOKEN_CACHE_DATA` 줄이 있고 파일 권한은 600이며, 홈 폴더 아래에 토큰 파일이 만들어지지 않는다

### Requirement: 요청하는 권한을 최소로 한다
시스템은 기본으로 태스크 읽기·쓰기 권한 하나만 요청해야 한다(SHALL). 읽기 전용 권한 설정이 켜져 있으면 읽기 권한만 요청해야 한다(SHALL). 동작 목록을 바꾸는 실행 설정(읽기 전용 실행, 삭제 도구 끄기)은 두지 않아야 한다(SHALL NOT). 읽기 권한만 받은 상태의 태스크 추가는 권한 부족 오류로 끝나야 한다(SHALL).

#### Scenario: 기본 권한
- **WHEN** 기본 설정으로 로그인한다
- **THEN** 동의 화면에서 요청하는 태스크 권한은 읽기·쓰기 하나뿐이다

#### Scenario: 읽기 전용 권한
- **WHEN** 읽기 전용 권한 설정을 켜고 로그인한다
- **THEN** 요청하는 권한은 태스크 읽기뿐이다

#### Scenario: 읽기 전용 실행
- **WHEN** To Do 모듈의 설정 항목과 명령 옵션을 확인한다
- **THEN** 읽기 전용 실행이나 삭제 도구 끄기 같은 동작 숨김 설정이 없다

### Requirement: 도구는 읽기와 태스크 추가로 고정한다
시스템은 앱에 목록 조회, 태스크 조회, 마감 범위 조회, 태스크 추가 동작만 내보내야 한다(SHALL). 태스크 수정, 완료 처리, 삭제, 목록 생성·수정·삭제, 체크리스트 동작은 내보내지 않아야 한다(SHALL NOT). 로그인과 로그인 상태 확인은 앱이 하루 실행에서 부르는 동작이 아니라 사람이 실행하는 명령이어야 한다(SHALL). 내보내는 동작의 목록은 허용 목록과 정확히 같아야 하며, 새 동작을 추가하려면 그 허용 목록을 의도적으로 고쳐야 한다(SHALL).

#### Scenario: 허용된 도구만 있음
- **WHEN** To Do 모듈이 앱에 내보내는 동작의 이름을 모은다
- **THEN** 허용 목록(목록 조회, 태스크 목록, 태스크 하나, 마감 범위, 태스크 추가)과 정확히 일치한다

#### Scenario: 위험한 도구가 없음
- **WHEN** 내보내는 동작에서 수정·완료·삭제 이름의 동작을 찾는다
- **THEN** 하나도 없다

### Requirement: 오류를 숨기지 않고 원인을 구분해서 알린다
시스템은 오류를 조용히 삼키지 않고 원인별로 구분된 코드와 메시지로 알려야 한다(SHALL). 구분은 로그인 필요, 로그인 만료, 권한 부족, 찾을 수 없음, 입력 오류, 요청 한도 초과, 서버 일시 장애를 포함해야 한다(SHALL). 요청 한도 초과일 때는 기다릴 시간을 알려야 한다(SHALL).

#### Scenario: 로그인 전 호출
- **WHEN** 로그인하지 않은 상태에서 태스크를 조회한다
- **THEN** 로그인이 필요하다는 오류 코드와, 앱의 To Do 로그인 명령을 실행하라는 안내를 돌려준다

#### Scenario: 읽기 전용으로 로그인한 뒤 추가 시도
- **WHEN** 읽기 권한만 받은 상태에서 태스크 추가를 요청한다
- **THEN** 권한이 부족하다는 오류를 돌려주고 아무것도 만들지 않는다

#### Scenario: 요청 한도 초과
- **WHEN** 서버가 요청이 너무 많다고 응답한다
- **THEN** 재시도 후에도 실패하면 요청 한도 초과 오류와 기다릴 시간을 알린다
