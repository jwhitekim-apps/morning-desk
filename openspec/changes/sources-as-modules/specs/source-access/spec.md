# Spec Delta

## Purpose
앱이 읽기 소스와 전송 대상(To Do, Gmail, GitHub, 폴리오, 카카오, 서버 점검)을 같은 프로세스의 모듈로 직접 호출하는 방식을 정한다. 프로토콜 층 없이도 앱이 쓸 수 있는 동작을 허용된 것으로만 고정하고, 소스별 비밀의 범위와 로그인 방법을 분명히 하는 것이 목적이다.

## ADDED Requirements

### Requirement: 앱은 소스를 같은 프로세스에서 직접 호출한다
시스템은 앱이 소스를 부를 때 별도의 프로세스를 띄우거나 MCP 같은 프로토콜을 거치지 않고 같은 프로세스의 함수 호출로 해야 한다(SHALL). 소스의 결과는 문자열로 바꾸었다 다시 해석하지 않고 정해진 구조 그대로 앱에 전달되어야 한다(SHALL). 앱의 실행에 소스별 사전 빌드가 필요하지 않아야 한다(SHALL).

#### Scenario: 하루 실행
- **WHEN** 앱이 브리핑을 한 번 실행한다
- **THEN** 소스를 위한 자식 프로세스가 하나도 생기지 않는다

#### Scenario: 빌드
- **WHEN** 저장소 루트에서 의존성을 설치하고 앱만 빌드한다
- **THEN** 앱을 실행할 수 있고 소스마다 따로 빌드할 필요가 없다

### Requirement: 앱이 받는 소스 동작은 허용 목록과 정확히 같다
시스템은 각 소스가 앱에 허용된 동작만 내보내야 한다(SHALL). 허용 목록은 소스마다 하나로 관리하고, 내보낸 동작의 이름이 그 목록과 정확히 같은지 테스트로 고정해야 한다(SHALL). 기존 항목의 수정·완료·삭제, 메일 발송·변경, 이슈·저장소 변경, 본인 외 대상에게 보내기, 명령 실행에 해당하는 동작은 내보내지 않아야 한다(SHALL NOT). 동작을 더하려면 그 목록과 명세를 의도적으로 고쳐야 한다(SHALL).

#### Scenario: 허용된 동작만 있음
- **WHEN** 각 소스가 앱에 내보내는 동작의 이름을 모은다
- **THEN** 소스별 허용 목록과 정확히 일치한다

#### Scenario: 금지된 동작을 더함
- **WHEN** 누군가 소스에 태스크 삭제나 메일 발송 동작을 더한다
- **THEN** 허용 목록 테스트가 실패한다

### Requirement: 쓰기 동작은 숨기지 않고 아예 두지 않는다
시스템은 허용되지 않은 동작을 설정이나 플래그로 감추는 방식으로 막지 않아야 한다(SHALL NOT). 허용되지 않은 동작은 코드에 존재하지 않아야 하고, 그래서 동작 목록을 바꾸는 실행 설정도 없어야 한다(SHALL).

#### Scenario: 숨김 설정이 없음
- **WHEN** 소스의 설정 항목과 명령 옵션을 확인한다
- **THEN** 동작을 감추거나 드러내는 설정(예: 읽기 전용 실행, 삭제 도구 끄기)이 없다

### Requirement: 각 소스는 자기 설정과 자기 토큰 키만 다룬다
시스템은 각 소스에 그 소스에 필요한 설정만 넘겨야 한다(SHALL). 각 소스는 `.env.local`에서 자기에게 정해진 토큰 키만 읽고 고쳐 써야 하고, 다른 소스의 키를 읽거나 바꾸지 않아야 한다(SHALL NOT). 소스의 결과, 오류 메시지, 로그에는 토큰과 비밀값이 나타나지 않아야 한다(SHALL NOT).

#### Scenario: 자기 키만 고쳐 씀
- **WHEN** 카카오 소스가 새 리프레시 토큰을 저장한다
- **THEN** `KAKAO_REFRESH_TOKEN` 줄만 바뀌고 다른 소스의 줄은 그대로다

#### Scenario: 다른 소스의 키를 요청함
- **WHEN** 한 소스의 코드가 자기에게 정해지지 않은 키를 읽거나 쓰려 한다
- **THEN** 파일을 열기 전에 오류가 난다

### Requirement: 로그인과 로그아웃은 앱의 명령으로 한다
시스템은 로그인이 필요한 소스(To Do, Gmail)의 로그인, 로그아웃, 로그인 상태 확인을 앱의 명령으로 제공해야 한다(SHALL). 이 명령은 사람이 터미널에서 직접 실행하는 것이며, 하루 실행 중에는 브라우저 로그인을 시작하지 않아야 한다(SHALL NOT). 로그인이 필요하면 실행은 그 소스를 실패로 기록하고 어떤 명령으로 로그인하는지 알려야 한다(SHALL).

#### Scenario: 처음 로그인
- **WHEN** 사람이 앱의 Gmail 로그인 명령을 실행한다
- **THEN** 브라우저 로그인 주소가 나오고, 승인하면 토큰이 `.env.local`에 저장된다

#### Scenario: 실행 중 로그인 필요
- **WHEN** 하루 실행 중 Gmail 토큰이 폐기되어 있다
- **THEN** 로그인을 시작하지 않고 실패 구역에 Gmail 로그인이 필요하다는 것과 로그인 명령이 적힌다
