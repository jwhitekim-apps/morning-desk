# gmail-tools Specification

## Purpose
에이전트가 Gmail을 읽기 전용으로 검색하고 메일 본문을 읽는 MCP 도구의 계약을 정한다. 보내기, 삭제, 수정은 도구로 주지 않아서 모델이 잘못 판단해도 메일함이 바뀌지 않게 하는 것이 목적이다.

## Requirements

### Requirement: 읽기 권한만 요청하고 쓰기 도구를 두지 않는다
시스템은 Gmail 읽기 전용 권한 하나만 요청해야 한다(SHALL). 메일 보내기, 삭제, 휴지통 이동, 보관, 라벨 변경, 읽음 표시 도구를 제공하지 않아야 한다(SHALL NOT). 도구 목록은 허용 목록과 정확히 같아야 하며, 새 도구를 추가하려면 그 목록을 의도적으로 고쳐야 한다(SHALL).

#### Scenario: 요청 권한
- **WHEN** 처음 로그인한다
- **THEN** 동의 화면에서 요청하는 Gmail 권한은 읽기 전용 하나뿐이다

#### Scenario: 허용된 도구만 있음
- **WHEN** 서버의 도구 목록을 조회한다
- **THEN** 허용 목록과 정확히 일치하고 쓰기에 해당하는 이름의 도구가 없다

#### Scenario: 쓰기를 시도해도 거부됨
- **WHEN** 같은 토큰으로 발송이나 휴지통 이동을 직접 시도해 본다
- **THEN** 서버가 권한 오류(403)로 거부한다

### Requirement: 검색식과 기간으로 메일을 검색한다
시스템은 Gmail 검색식, 조회 기간(일), 최대 개수를 받아 조건에 맞는 메일의 요약 목록을 돌려주어야 한다(SHALL). 요약에는 메일 번호, 스레드 번호, 제목, 보낸 사람, 날짜, 미리보기를 포함해야 한다(SHALL). 결과가 최대 개수에 걸려 잘렸으면 잘렸다는 사실을 알려야 한다(SHALL).

#### Scenario: 키워드와 기간
- **WHEN** "학회" 또는 "교수"가 들어간 최근 2일 안의 메일을 검색한다
- **THEN** 조건에 맞는 메일의 요약이 날짜 최신순으로 나온다

#### Scenario: 결과 없음
- **WHEN** 조건에 맞는 메일이 없다
- **THEN** 빈 목록을 오류 없이 돌려준다

#### Scenario: 개수 제한에 걸림
- **WHEN** 조건에 맞는 메일이 최대 개수보다 많다
- **THEN** 최대 개수만큼만 돌려주고 잘렸다는 표시를 함께 준다

### Requirement: 메일 본문을 길이 상한 안에서 읽는다
시스템은 메일 번호로 본문을 텍스트로 돌려주어야 한다(SHALL). 일반 텍스트 부분이 있으면 그것을 쓰고, 없으면 HTML에서 태그를 제거한 텍스트를 써야 한다(SHALL). 본문이 길이 상한을 넘으면 상한까지만 돌려주고 잘렸다는 사실을 알려야 한다(SHALL).

#### Scenario: 여러 부분으로 된 메일
- **WHEN** 일반 텍스트와 HTML이 함께 있는 메일의 본문을 읽는다
- **THEN** 일반 텍스트 부분의 내용이 나온다

#### Scenario: HTML만 있는 메일
- **WHEN** HTML만 있는 메일의 본문을 읽는다
- **THEN** 스크립트와 스타일을 뺀 텍스트가 나온다

#### Scenario: 긴 본문
- **WHEN** 본문이 길이 상한보다 길다
- **THEN** 상한까지의 텍스트와 함께 잘렸다는 표시가 나온다

### Requirement: 스레드의 첫 메일 제목을 함께 알린다
시스템은 검색 결과의 각 메일에 같은 스레드에서 가장 먼저 받은 메일의 제목을 함께 돌려주어야 한다(SHALL). 스레드는 스레드 번호마다 한 번만 조회해야 한다(SHALL). 스레드 조회에 실패해도 메일 요약은 돌려주고, 첫 메일 제목을 얻지 못했다는 사실을 표시해야 한다(SHALL).

#### Scenario: 답장이나 후속 메일
- **WHEN** "[추가 사항 확인 요망] 학회 안내"라는 제목의 후속 메일이 "학회 안내" 스레드에 있다
- **THEN** 후속 메일의 요약에 스레드 첫 메일 제목 "학회 안내"가 함께 나온다

#### Scenario: 같은 스레드의 여러 메일
- **WHEN** 검색 결과에 같은 스레드의 메일이 세 통 있다
- **THEN** 스레드 조회는 한 번만 일어난다

#### Scenario: 스레드 조회 실패
- **WHEN** 스레드 조회가 오류로 끝난다
- **THEN** 메일 요약은 그대로 나오고 첫 메일 제목은 얻지 못했다고 표시된다

### Requirement: 토큰과 메일 본문을 보호한다
시스템은 로그인 토큰(리프레시 토큰)을 저장소 루트의 `.env.local`(권한 600)에 `GMAIL_REFRESH_TOKEN` 키로 저장해야 한다(SHALL). OAuth 클라이언트 정보는 `.env.local`의 `GMAIL_CLIENT_ID`와 `GMAIL_CLIENT_SECRET`에서 읽어야 한다(SHALL). 토큰은 도구 응답과 로그에 나타나지 않아야 한다(SHALL NOT). 메일 본문과 제목은 로그에 남기지 않아야 한다(SHALL NOT).

#### Scenario: 토큰 파일 권한
- **WHEN** 로그인한 뒤 `.env.local`을 확인한다
- **THEN** `GMAIL_REFRESH_TOKEN` 줄이 있고 파일 권한은 600이며, 홈 폴더 아래에 토큰 파일이 만들어지지 않는다

#### Scenario: 로그에 내용이 없음
- **WHEN** 검색과 본문 읽기를 실행한 뒤 로그를 확인한다
- **THEN** 토큰, 메일 제목, 메일 본문이 없고 건수와 소요 시간 같은 값만 있다

### Requirement: 오류를 숨기지 않고 구분해서 알린다
시스템은 로그인 필요, 토큰 만료·폐기(예: 갱신 토큰이 더는 유효하지 않음), 권한 부족, 요청 한도 초과, 서버 일시 장애를 구분된 오류 코드와 메시지로 알려야 한다(SHALL). 토큰이 만료·폐기된 경우에는 다시 로그인하라고 안내해야 한다(SHALL).

#### Scenario: 갱신 토큰이 폐기됨
- **WHEN** 저장된 갱신 토큰이 더는 유효하지 않다
- **THEN** 토큰이 만료되었다는 오류와 다시 로그인하라는 안내를 돌려준다

#### Scenario: 요청 한도 초과
- **WHEN** Gmail이 요청이 너무 많다고 응답한다
- **THEN** 재시도 후에도 실패하면 요청 한도 초과 오류와 기다릴 시간을 알린다
