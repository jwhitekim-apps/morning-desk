# token-env-file Specification

## Purpose
MCP 서버들이 로그인 토큰을 저장소 루트의 `.env.local` 한 곳에 읽고 고쳐 쓰는 공통 규칙을 정한다. 비밀값과 토큰을 한 파일에서 관리하면서도, 여러 서버가 같은 파일을 고쳐 쓰다 다른 비밀을 잃거나 파일을 깨뜨리지 않게 하는 것이 목적이다.

## Requirements

### Requirement: 토큰은 루트의 .env.local에 서버마다 정해진 키로 저장한다
시스템은 각 MCP 서버의 토큰을 저장소 루트의 `.env.local`에 `KEY=VALUE` 한 줄로 저장해야 한다(SHALL). 서버는 자기에게 정해진 키만 읽고 쓸 수 있어야 하고(SHALL), 다른 서버의 키를 읽거나 바꾸지 않아야 한다(SHALL NOT). 값은 줄바꿈이 없는 한 줄이어야 한다(SHALL).

#### Scenario: 자기 키만 다룬다
- **WHEN** 카카오 서버가 새 리프레시 토큰을 저장한다
- **THEN** `KAKAO_REFRESH_TOKEN` 줄만 바뀌고 Gmail, To Do, GitHub의 줄은 그대로다

#### Scenario: 다른 서버의 키를 요청함
- **WHEN** 한 서버의 코드가 자기에게 정해지지 않은 키를 읽거나 쓰려 한다
- **THEN** 파일을 열기 전에 오류가 난다

#### Scenario: 긴 토큰
- **WHEN** 여러 줄로 된 토큰 캐시를 저장한다
- **THEN** 한 줄로 인코딩되어 저장되고, 다시 읽으면 원래 내용과 같다

### Requirement: 다른 줄과 주석은 바꾸지 않는다
시스템은 키를 고쳐 쓸 때 그 키의 줄만 바꾸고 다른 줄, 빈 줄, 주석, 순서를 그대로 두어야 한다(SHALL). 키가 없으면 파일 끝의 토큰 구역에 새 줄로 더해야 한다(SHALL).

#### Scenario: 정리된 파일
- **WHEN** 주석과 빈 줄로 그룹을 나눈 `.env.local`에서 한 키를 고쳐 쓴다
- **THEN** 그 줄의 값만 바뀌고 나머지 내용은 글자 하나 바뀌지 않는다

#### Scenario: 처음 저장
- **WHEN** 파일에 아직 그 키가 없다
- **THEN** 토큰 구역에 새 줄이 더해지고 기존 내용은 그대로다

### Requirement: 동시에 써도 내용을 잃지 않고 파일이 깨지지 않는다
시스템은 여러 서버가 같은 파일을 동시에 고쳐 써도 서로의 변경을 잃지 않아야 한다(SHALL). 쓰는 도중 중단되어도 반쯤 쓴 파일이 남지 않아야 한다(SHALL). 쓴 뒤의 파일 권한은 600이어야 한다(SHALL).

#### Scenario: 두 서버가 함께 갱신
- **WHEN** 두 서버가 거의 같은 시각에 각자의 키를 고쳐 쓴다
- **THEN** 두 변경이 모두 파일에 남는다

#### Scenario: 쓰는 도중 중단
- **WHEN** 쓰는 도중 프로세스가 끝난다
- **THEN** 파일은 이전 내용 그대로이거나 새 내용 그대로이고, 섞이거나 잘린 내용이 아니다

#### Scenario: 권한
- **WHEN** 키를 고쳐 쓴 뒤 파일 권한을 확인한다
- **THEN** 권한은 600이다

### Requirement: 토큰 값은 응답과 로그에 나오지 않는다
시스템은 `.env.local`에서 읽거나 쓴 값을 도구 응답, 오류 메시지, 로그에 남기지 않아야 한다(SHALL NOT). 읽기나 쓰기에 실패하면 키 이름과 실패 이유만 알려야 한다(SHALL).

#### Scenario: 쓰기 실패
- **WHEN** 파일에 쓸 수 없어 실패한다
- **THEN** 오류에는 키 이름과 이유만 있고 값은 없다

### Requirement: 파일 위치를 설정할 수 있다
시스템은 `MY_TASK_ENV_FILE`에 적힌 경로의 파일을 써야 한다(SHALL). 설정이 없으면 서버가 설치된 저장소의 루트에 있는 `.env.local`을 써야 한다(SHALL). 파일이 없으면 로그인이 필요하다고 알려야 한다(SHALL).

#### Scenario: 비서가 띄운 서버
- **WHEN** 비서가 서버를 띄우면서 `MY_TASK_ENV_FILE`을 넘긴다
- **THEN** 서버는 그 파일에서 토큰을 읽고 그 파일에 고쳐 쓴다

#### Scenario: 직접 실행한 서버
- **WHEN** 설정 없이 서버를 직접 실행한다
- **THEN** 저장소 루트의 `.env.local`을 쓴다

### Requirement: 기존 토큰 파일을 .env.local로 옮길 수 있다
시스템은 홈 폴더 아래의 기존 토큰 파일을 읽어 `.env.local`의 정해진 키로 옮기는 명령을 제공해야 한다(SHALL). 옮긴 값을 다시 읽어 원래 값과 같은지 확인한 뒤에만 원래 파일을 지워야 한다(SHALL). 옮기기 전에 `.env.local`의 백업을 권한 600으로 남겨야 한다(SHALL).

#### Scenario: 옮기기
- **WHEN** To Do, Gmail, 카카오, 벨루의 토큰 파일이 있는 상태에서 옮기기 명령을 실행한다
- **THEN** 네 키가 `.env.local`에 생기고, 확인을 마친 원래 파일은 지워지며, 백업 파일이 남는다

#### Scenario: 일부 파일이 없음
- **WHEN** 벨루 세션 파일이 없다
- **THEN** 있는 것만 옮기고 없는 것은 건너뛰었다고 알린다

#### Scenario: 확인 실패
- **WHEN** 옮긴 값을 다시 읽었더니 원래 값과 다르다
- **THEN** 원래 파일을 지우지 않고 오류를 알린다
