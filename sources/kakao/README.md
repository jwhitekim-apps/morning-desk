# morning-desk / kakao 소스 모듈

[`morning-desk`](../../README.md) 앱의 **알림 보내는 부분**입니다. 카카오톡 **"나에게 보내기"**로 텍스트를 보내는 모듈이고, 앱이 같은 프로세스에서 import 해서 씁니다. 브리핑을 어떻게 구성하고 나눌지는 앱의 몫이고, 이 모듈은 정해진 글자를 나에게 보내는 일만 합니다. 코드는 직접 작성했고 외부 코드를 가져오지 않았습니다.

## 하는 일

`createKakaoSource(config, { logger })`가 아래 함수 하나만 담은 객체를 돌려줍니다. 설정 상태(REST API 키, 클라이언트 시크릿, 리프레시 토큰이 있는지, 값 없이)는 앱의 `auth-status` 명령이 `kakaoStatus(config)`로 보여 줍니다.

| 함수 | 종류 | 설명 |
|---|---|---|
| `sendManyToMe(messages, { dryRun? })` | 보내기 | 1~3통을 순서대로 나에게 보내기. 하나라도 검사에 걸리면 하나도 보내지 않음. `dryRun: true`이면 보내지 않고 내용과 글자 수만 돌려줌 |

- **받는 사람을 지정하는 입력이 없습니다.** 항상 로그인한 본인에게만 갑니다. 친구에게 보내기와 대화 읽기 함수는 없고, 코드가 부르는 카카오 주소도 토큰 갱신과 나에게 보내기, 두 곳뿐입니다(`test/allowlist.test.ts`가 함수 목록과 입력, 주소를 고정합니다). 함수를 더하려면 그 허용 목록과 명세(`openspec/specs/kakao-send-tools`)를 의도적으로 고칩니다.
- **한 통은 200자까지**(코드 포인트 기준, 이모지 한 개가 한 글자)입니다. 넘으면 **자르지 않고 거부**하며, 넘은 글자 수를 오류로 알립니다. 나누고 서식을 입히는 일은 앱이 합니다. 오류와 로그에는 본문이 들어가지 않습니다.
- 인증 오류(401)면 **한 번만** 갱신해서 다시 보냅니다. 서버 오류나 네트워크 오류는 **다시 보내지 않습니다**(같은 메시지가 두 번 가는 것을 막기 위해). 이때 "보내지 못했다/보냈는지 확인하지 못했다"를 오류에 분명히 적습니다. 여러 통 중간에 실패하면 몇 통이 나갔는지 알려 줍니다.
- 드라이런: 인자 `dryRun`, 또는 환경 변수 `KAKAO_DRY_RUN=1`(이 경우 앱이 `dryRun: false`로 해도 강제로 드라이런). 한도 검사는 실제 전송과 같습니다.

## 한계

- **카카오톡을 읽을 수는 없습니다.** 카카오가 대화를 읽는 API를 주지 않습니다. 보내기 전용입니다.
- **알림이 울리지 않을 수 있습니다.** 메시지는 "나와의 채팅"에 도착하지만 폰 푸시 알림이 오지 않는 것이 이전 운영에서 실제로 확인되었습니다. 이 모듈은 전송만 책임지고, 알림 문제는 별도 변경으로 다룹니다.

## 설정

Node 20 이상. 설치와 검사는 저장소 루트에서 합니다(npm workspace). 이 모듈은 따로 빌드하지 않고, 앱을 빌드할 때 함께 묶입니다.

```bash
npm ci --ignore-scripts   # 잠금 파일 그대로 설치, 의존 패키지의 설치 스크립트는 실행하지 않음
npm test -w sources/kakao
```

설정(앱이 `.env.local`에서 읽어 `loadConfig`로 넘김):

| 이름 | 설명 |
|---|---|
| `KAKAO_REST_API_KEY` | 카카오 개발자 앱의 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 앱에서 클라이언트 시크릿을 켠 경우 |
| `KAKAO_LINK_URL` | 말풍선을 눌렀을 때 열 주소(카카오 텍스트 템플릿이 링크를 요구함). 실제 전송에 필요 |
| `KAKAO_DRY_RUN` | `1`이면 모든 전송이 드라이런 |

리프레시 토큰은 환경 변수가 아니라 루트 `.env.local`(권한 600)의 `KAKAO_REFRESH_TOKEN` 줄에서 모듈이 직접 읽고, 갱신 응답에 새 값이 오면 그 줄만 고쳐 씁니다(잠금 → 임시 파일 → 바꿔치기라 쓰다 끊겨도 깨지지 않음). 액세스 토큰은 메모리에만 둡니다. 저장 위치는 `MY_TASK_ENV_FILE`, 없으면 저장소 루트의 `.env.local`입니다. 파일 끝의 `# --- 토큰 (자동 갱신, 직접 고치지 마세요)` 구역은 모듈이 고쳐 쓰므로 손으로 고치지 않습니다. 예전처럼 홈 폴더에 토큰 파일이 남아 있으면 앱의 `morning-desk migrate-tokens`(먼저 `--dry-run`)로 옮깁니다.

## 토큰이 만료되면

리프레시 토큰은 약 60일 수명이고, 매일 쓰면 갱신 때마다 연장되는 것으로 보이지만 확인된 사실은 아닙니다. 만료되면 `auth_expired`와 "카카오 로그인을 다시 하라"는 안내를 돌려줍니다. 새 토큰은 카카오 개발자 콘솔의 도구로 발급받거나 인가 코드 흐름으로 받아서(`talk_message` 동의 필요) 루트 `.env.local`의 `KAKAO_REFRESH_TOKEN` 줄을 그 값으로 바꿉니다(앱이 돌지 않을 때).

## 개인정보

- 토큰과 클라이언트 비밀값은 결과, 오류, 로그에 나타나지 않습니다.
- 로그는 허용한 필드(통수, 글자 수, 소요 시간, 오류 분류)만 남기는 방식이라 **메시지 본문이 기록되지 않습니다**(`test/privacy.test.ts`).
- 오류는 카카오가 보낸 설명문을 쓰지 않고 고정 문구와 분류 코드를 씁니다.
- 실제 전송 결과는 본문을 되돌려주지 않습니다. 드라이런만 확인용으로 본문을 돌려줍니다.
